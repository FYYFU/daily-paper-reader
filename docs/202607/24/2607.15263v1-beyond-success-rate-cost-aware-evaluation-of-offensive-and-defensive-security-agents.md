## 摘要
安全代理评估通常衡量在慷慨推理预算下的峰值进攻能力，强调漏洞发现、漏洞利用开发、渗透测试和CTF完成。此类测量有用但不完整：在运营安全中，每个推理步骤、工具调用、遥测查询和扩充请求都会消耗预算。我们通过成本-成功视角评估语言模型安全代理，涉及进攻性Cybench挑战和防御性Splunk BOTS v1调查挑战。我们不仅报告最佳情况下的成功，还比较固定成本水平下的模型，并按推理支出和工具支出分解性能。我们的结果显示了红队和蓝队任务的不同扩展规律。进攻性CTF性能随着测试时计算的增加而提高，扩展的开源模型可以在保持成本竞争力的同时接近前沿专有系统。防御性SOC调查不能以相同方式扩展：成功更多依赖于纪律性的工具使用、遥测导航和选择性扩充，而不仅仅是原始推理预算。我们认为，安全代理基准测试应衡量经济效率和运营适配性，与任务成功并重。成本感知的SOC原生评估能更清晰地展示哪些模型在实际中有用，以及防御代理仍需改进之处。我们提供了一个交互式网站展示结果：https://evals.frontier.security。

## Abstract
Security-agent evaluations commonly measure peak offensive capability under generous inference budgets, emphasizing vulnerability discovery, exploit development, penetration testing, and CTF completion. Such measurements are useful but incomplete: in operational security, every reasoning step, tool call, telemetry query, and enrichment request consumes budget. We evaluate language-model security agents through this cost-success lens on offensive Cybench challenges and defensive Splunk BOTS v1 investigation challenges. Instead of reporting only best-case success, we compare models at fixed cost levels and decompose performance by inference spend and tool spend. Our results show distinct scalingregimes for red- and blue-team tasks. Offensive CTF performance improves with additional test-time compute, and scaled open-weight models can approach frontier proprietary systems while remaining cost-competitive. Defensive SOC investigation does not scale in the same way: success depends more heavily on disciplined tool use, telemetry navigation, and selective enrichment than on raw reasoning budget alone. We argue that security-agent benchmarks should measure economic efficiency and operational fit alongside task success. Cost-aware, SOC-native evaluations provide a clearer picture of which models are practically useful today and where defensive agents still need to improve. We present an interactive website with our results https://evals.frontier.security.

## 1. 核心问题与整体含义（研究动机与背景）
- **问题**：当前安全代理（AI安全智能体）评估普遍聚焦于**峰值成功率**——在慷慨的推理预算下衡量进攻能力（CTF解题、漏洞利用、渗透测试等），却完全忽略运营安全中的**成本**（每次推理步骤、工具调用、遥测查询、外部情报扩充均消耗预算）。
- **背景**：SOC（安全运营中心）需要代理在有限预算内高效导航遥测、选择搜索、决定何时付费扩充，而非仅追求极致能力。因此，作者引入**成本–成功**视角，将进攻（红队）和防御（蓝队）代理对齐在同一轴——固定预算下“每美元可买多少能力”。
- **意义**：呼吁安全代理基准应同时衡量**经济效率**和**操作适配**，而非单一的成功率排行榜。

## 2. 方法论：核心思想、技术细节与流程
### 核心思想
- 将**成功率**转化为**操作问题**：给定固定成本上限，模型能解决多少任务？成本被分解为**推理费用**（模型token）和**定价工具费用**（外部API调用）。
- 进攻型CTF：边际开销主要用于推理和命令执行；防御型SOC：还包括Splunk查询、事件检查、WHOIS/DNS/Web搜索等付费调用。

### 关键技术细节
- **框架**：基于 **Inspect**（UK AI Security Institute 2024）搭建评测。
- **Agent架构**：ReAct风格，启用自动压缩（auto-compaction），在上下文达90%窗口时触发压缩（优先使用API原生压缩，回退摘要压缩）。
- **成本预算控制**：通过Inspect的`budget`选项设置每样本运行总成本上限，超预算即中止并标记为失败。代理本身**不知晓**成本/预算，但知晓某些昂贵工具调用限制。
- **成本会计**：
  - 进攻型（Cybench）：仅模型token成本（bash/python工具零成本）。
  - 防御型（BOTS v1）：模型token成本 + 定价工具费用（Brave Search $0.005/次，WhoisXMLAPI preview $0.0258/次，purchase $1.29/次；VirusTotal/DNS/WHOIS免费）。
- **拒绝处理**：基于文本匹配和provider content_filter标志检测拒绝；Cybench中拒绝被视为失败，BOTS v1中拒绝可部分共存（若后续尝试成功可得分）。

### 算法/流程说明（文字描述）
1. 对每个任务样本，使用ReAct agent迭代推理，可调用预设工具集。
2. 每次调用产生token消耗和可能的工具账单。
3. 总运行成本 = sum(推理费) + sum(定价工具费)。
4. 当累计成本达到预算上限时强制终止，未完成的任务计为失败。
5. 最终计算固定预算下的成功率/分数，并绘制随预算变化的缩放曲线。

## 3. 实验设计
### 数据集/场景
- **进攻型（红队）**：**Cybench hard variant**（Inspect Evals实现），39个专业CTF挑战，源自HackTheBox、Glacier、SEKAI、HKCert竞赛，涵盖密码、Web漏洞、逆向、取证、二进制利用等。仅提供bash和python工具，提交flag（最多3次）。
- **防御型（蓝队）**：**Splunk BOTS v1**（公开数据集），31个计分问题，涉及Po1s0n1vy Web篡改和Cerber勒索软件调查。提供Splunk搜索、事件检查、VirusTotal/WHOIS/DNS/Brave Search/bash/python工具。设置工具调用上限（WHOIS/VT各3次，Web搜索5次）。分数按官方点数（10300点）计算，正确答案得分减去提示惩罚。23个问题提供前提上下文依赖。

### 对比方法/模型
- **评测模型**：GPT-5.5；GPT-5.6 Luna、Terra、Sol；Claude Opus 4.8、Fable 5；DeepSeek v4 Flash、Pro。GPT-5.6和Fable使用高推理努力（high reasoning effort）。
- **消融/控制**：
  - **回顾性预算上限**：对已完成的轨迹施加更低预算（如$0.80/样本），比较相同trajectory下不同预算的表现。
  - **污染控制（BOTS v1）**：无工具对照组（不提供Splunk/Web等，只靠问题文本和前提知识回答），检测是否模型记忆了公开答案。

## 5. 实验数量与充分性
- **主要实验**：
  - Cybench：8个模型设置（含不同预算行），每个模型跑3个epoch（独立重复），共39个挑战 × 3 epoch = 117样本-epoch。
  - BOTS v1：10个模型设置（含不同预算、高努力、污染控制），每个模型跑3个epoch，共31个问题 × 3 epoch = 93样本-epoch。
  - 回顾性预算分析：对4个模型（GPT-5.5, Claude Opus 4.8, DeepSeek v4 Flash/Pro）做每次$0.80上限回溯。
  - 污染控制：2个模型（Claude Opus 4.8, GPT-5.5）各2个条件（有前提/无前提）。
- **充分性评价**：
  - **优点**：多模型、多预算点、多epoch平均，提供95% bootstrap置信区间，区分进攻/防御两种工作负载，包含控制实验。
  - **局限**：非前瞻性随机矩阵（部分为回顾性）；BOTS v1数据集陈旧且公开，污染控制显示模型可仅凭文本答出50-75%分数，说明绝对分数不可靠；仅一个防御数据集（BOTS v1），未扩展至v2/v3；部分模型因provider限制（拒绝/内容过滤）导致得分偏低（Fable 0%），难以分离能力与政策。

## 6. 主要结论与发现
1. **进攻型CTF存在成本缩放**：更多推理预算可提高成功率。例如DeepSeek v4 Flash从$0.80到$2.10提升+10.3 pp（76.1% → 86.4%）；Claude Opus 4.8从$0.80到满预算提升+18.8 pp；但GPT-5.5在低预算下已解决多数，提升仅+2.6 pp。
2. **防御型SOC无明显成本缩放**：DeepSeek v4 Flash预算从$2.10翻倍至$4.20，分数仅从73.0%提升至73.9%（bootstrap区间不显著）。高工具调用量并不带来高分，Claude Opus 4.8以最少工具调用（603次）取得最高分（93.9%）。
3. **防御成功的关键是工具纪律**：非原始推理预算，而是循证使用Splunk、选择性付费扩充、正确验证答案。
4. **公共SOC基准需污染控制**：无工具探针中，Claude Opus 4.8在包含前提上下文时得74.8%，仅问题文本时50.0%，表明绝对分数不能直接视为现场调查能力。
5. **最强操作点**：进攻端GPT-5.5（94.1%成功率，$1.16/解得）；防御端Claude Opus 4.8（93.9%分数，$2.98/千点）。

## 7. 优点
- **创新的成本感知视角**：将经济效率纳入安全代理评估，首次系统对比进攻与防御的不同缩放规律。
- **细粒度成本分解**：区分推理费与工具费，对防御场景外部API定价精确记账。
- **自注意力污染控制**：通过无工具对照组揭示公开基准的泄露问题，提升结论可信度。
- **交互式网站**：公开结果以利于复现与探索。
- **多模型多预算点**：提供5个预算水平下的性能曲线，辅以bootstrap置信区间，增强统计稳健性。

## 8. 不足与局限
- **实验覆盖不足**：
  - 仅使用一个防御数据集（BOTS v1），且版本旧（2017），未覆盖现代SOC环境（如云、EDR）。
  - 进攻端仅39个CTF挑战，未涵盖真实漏洞利用（如CVE-Bench、BountyBench）。
  - 未测试更近期模型（如GPT-5.6已包含，但其他前沿模型可能缺失）。
- **偏差风险**：
  - BOTS v1是公共数据集，模型可能通过训练数据记忆答案（污染控制已证实），导致防御得分虚高，绝对数字不可信。
  - 部分模型因provider拒绝策略（Fable全拒绝）无法获得真实能力，可能低估其潜力。
- **方法局限**：
  - 回顾性预算分析不是真正的随机控制，可能引入选择偏差（高预算轨迹本身可能来自更困难样本）。
  - 消息限制（250条）可能导致高调用模型（如DeepSeek v4 Flash）被截断，分数偏低。
  - 成本模型简化：未计入Splunk基础设施、人工审查、存储等运营成本；工具定价仅按公布API费率，未考虑缓存、批量折扣等。
- **应用限制**：
  - 评估框架（Inspect）和厂商API可能与真实SOC环境部署有差异（如延迟、并发限制）。
  - 结论基于当前模型代次，随模型更新可能改变。
