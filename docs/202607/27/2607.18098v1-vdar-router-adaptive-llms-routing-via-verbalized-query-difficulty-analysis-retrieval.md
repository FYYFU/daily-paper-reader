## 摘要
大型语言模型越来越多地应用于实际系统中，这使得高效的模型选择对于降低部署成本至关重要。LLM路由已成为一种实用方案，可在期望的成本-性能权衡下将每个输入查询分配给合适的模型。现有路由方法通常从输入查询的表面语义或嵌入相似性来估计模型适用性。然而，这类方法可能忽略查询的潜在难度，导致路由决策欠佳。为应对这一挑战，我们提出VDAR-Router，一种基于难度感知的检索路由框架。对于每个输入查询，VDAR-Router首先生成显式的难度分析，然后检索具有相似难度特征的历史示例，基于检索记录估计候选模型的适用性，并使用考虑性能和成本的奖赏函数选择模型。在三个数据集上的实验表明，VDAR-Router相比现有基线始终实现更优的成本-性能权衡。这些结果证明了难度感知检索对无训练LLM路由的有效性。案例研究进一步显示，显式查询分析有助于检索更相关的示例，并支持更可靠的路由决策。

## Abstract
Large language models are increasingly used in practical systems, making efficient model selection important for reducing deployment cost. LLM routing has emerged as a practical solution for allocating each input query to an appropriate model under a desired cost-performance trade-off. Existing routing methods often estimate model suitability from the surface semantics or embedding similarity of the input query. However, such methods may ignore the underlying difficulty of a query, leading to suboptimal routing decisions. To address the challenge, we propose VDAR-Router, a difficulty-aware retrieval-based routing framework. For each input query, VDAR-Router first generates an explicit difficulty analysis. It then retrieves historical examples with similar difficulty profiles. Based on the retrieved records, it estimates candidate model suitability and selects the model using a reward function that considers both performance and cost. Experiments on three datasets show that VDAR-Router consistently achieves better cost-performance trade-offs than existing baselines. These results demonstrate the effectiveness of difficulty-aware retrieval for training-free LLM routing. Case studies further show that explicit query analysis helps retrieve more relevant examples and supports more reliable routing decisions.

## 1. 核心问题与整体含义（研究动机和背景）
- **研究动机**：大语言模型（LLM）部署中，常需在“最佳模型的高成本”与“低成本模型的弱性能”之间权衡。现有LLM路由方法主要依赖查询的表面语义或嵌入相似性来估计模型适用性，却忽视了查询的潜在难度，导致路由决策次优（例如，将需要复杂推理的简单文本归类为困难，或反之）。
- **核心问题**：如何动态地、基于难度感知地为输入查询选择最合适的LLM，在保证响应质量的同时控制推理成本。
- **整体含义**：引入“显式查询难度分析”作为检索目标，可使路由更精准地匹配所需能力，实现无需额外训练的、更可靠且成本高效的LLM路由。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：通过生成查询的显式难度分析（verbalized query difficulty analysis），检索历史中具有相似难度模式的查询记录，并基于检索结果评估各候选模型在性能与成本上的综合收益，从而选择最优模型。
- **关键技术细节**：
  1. **Difficult Analyst**：一个LLM代理（如Gemma4-31B或Qwen3.5-2B），在系统提示中预设7个能力维度（推理、理解、指令遵循、代理能力、知识检索、编码、多语言），对输入查询输出结构化的难度分析文本。
  2. **离线收集**：对所有训练查询生成难度分析，经嵌入模型（Qwen3-Embedding-0.6B）编码后存入数据库。
  3. **在线路由**：对测试查询同样生成难度分析并嵌入，在数据库中检索top-k最相似的难度分析（而非原始查询），得到对应的历史查询及模型表现记录。
  4. **奖励排序**：基于检索结果计算每个模型的奖赏值：\( R(m|q) = \frac{1}{k} \sum_{i=1}^k [\alpha \cdot p_m(q_i^r) - \beta \cdot c_m(q_i^r)] \)，其中 \( p_m \) 为性能（归一化正确率），\( c_m \) 为成本（归一化推理费用），\( \alpha+\beta=1 \)（本文设置α=0.8或0.6）。
  5. **最终选择**：奖赏值最高的模型 \( \hat{m} = \arg\max_{m\in M} R(m|q) \)。

## 6. 主要结论与发现
- VDAR-Router在三个数据集上均实现了**最佳成本-性能权衡**（奖赏最高），且在ArenaExpert5K上获得最高成对准确率和Spearman相关性。
- 消融实验表明**奖赏重排序**和**难度分析检索**两个组件均至关重要，缺一不可。
- 当训练数据减少（50%分割）时，VDAR-Router仍优于所有基线，显示其样本效率。
- 超参数分析显示，增大k（检索数量）通常在RouterBench/LLMRouterBench上提高稳定性和性能；α越大（更重视性能）奖赏越高。
- 案例研究证实，难度分析检索出的邻居在所需能力上与输入查询更匹配，而原始查询检索易被表面语义误导。
- Rasch难度对齐实验定量证明，难度分析检索出的示例与输入查询的难度差距显著小于查询嵌入检索和随机检索。

## 7. 优点
- **无需训练**：VDAR-Router是训练自由（training-free）框架，只需离线生成难度分析并嵌入，省去模型训练开销和训练数据依赖。
- **可解释性**：每个路由决策都附带显式的难度分析文本，便于调试和人工审查。
- **精细的能力匹配**：通过分析抽象能力维度（如推理、编码等），能区分表面相似但难度迥异的查询（如简单算术vs复杂微积分），突破语义相似性局限。
- **成本控制灵活**：奖赏函数允许通过α/β参数平滑调节性能与成本的偏好。
- **跨任务通用性**：在常规性能评分和成对偏好两种评估设定下均有效。

## 8. 不足与局限
- **测试时难度分析计算成本**：每次路由需要调用一次LLM生成难度分析，引入了额外延迟和API调用费用。尽管作者尝试使用2B小模型仍有效，但延迟问题未量化对比。
- **偏好设置下的局限性**：在ArenaExpert5K上，增大检索k未带来单调收益，作者认为可能因偏好标签受风格、主观偏差等非难度因素影响，说明难度相似性假设在主观评价场景下不完全成立。
- **能力维度的预设依赖**：7个维度由人工指定，可能不覆盖所有任务类型；过度结构化可能遗漏某些混合能力。
- **实验覆盖**：仅评测英文数学、编程、通用问答等任务；未涉及多语言、长上下文或工具调用等新兴场景。
- **公平性考量**：对比基线中，部分方法（如RouterDC、ICL-Router）需额外训练数据或微调，而VDAR-Router无需训练，比较在不同资源消耗条件下进行，但论文未控制“训练成本”作为单独指标。
