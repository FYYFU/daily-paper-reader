## 摘要
运行时护栏在不可逆工具调用之前起作用，但其保证取决于策略状态的可表示性、评判者观察到什么以及干预是否会改变未来行为。我们区分三个问题。首先，相对于固定的预言谓词，确定性门控强制执行恰好是其寄存器模型识别的良好前缀的非空安全策略；策略非平凡性在使用两个可递减计数器时是不可判定的，但对于可分离单调片段则属于PSPACE。其次，在固定外生规律下，内曼-皮尔逊给出了精确的误拦截/漏报边界，而一致标定则给出了有限样本边际证书，可能通过全拦截实现。第三，一旦拦截改变了未来提议，静态分数和无门控轨迹不需要识别闭环边界；相反，一个指定的有限受控模型会产生一个占用程序。有界表示攻击增加了鲁棒性裕度，因此仅良性标定无法转移。实验通过静态诊断、受控模型枚举、表示重写和配对闭环重运行来针对这些区分。

## Abstract
Runtime guardrails act before irreversible tool calls, but their guarantees depend on what policy state is representable, what a judge observes, and whether intervention changes future behavior. We separate three questions. First, relative to fixed oracle predicates, a deterministic gate enforces exactly the nonempty safety policies whose good prefixes its register model recognizes; policy nontriviality is undecidable with two decrementable counters but in PSPACE for a separable monotone fragment. Second, under a fixed exogenous law, Neyman-Pearson gives the exact false-block/miss frontier and conformal calibration gives a finite-sample marginal certificate, possibly via block-all. Third, once blocking changes future proposals, static scores and ungated trajectories need not identify the closed-loop frontier; a specified finite controlled model instead yields an occupancy program. Bounded representation attacks add a robustness margin, so benign calibration alone does not transfer. Experiments target these distinctions through static diagnostics, controlled-model enumeration, representation rewrites, and paired closed-loop reruns.

- **关键技术细节**：
  - **T1 – Oracle符号层面**：
    - 定义门控（gate）为确定性的寄存器自动机，要求它基于已提交的效果历史和Oracle谓词位决定允许/阻止/替换。
    - 定理1：一个非空策略能被( T ; Π )-门有效强制执行当且仅当它是安全性（safety）且其好前缀语言可被该类自动机识别。
    - 严格弱于编辑自动机（例如“每次支付后必须确认”的更新性质不可被门强制执行）。
  - **T2 – 统计与顺序边界**：
    - 对外生（exogenous）一步决策，Neyman-Pearson引理给出精确的错误拦截率 ROC 边界（定理2）。
    - 当拦截改变未来提议时，静态 ROC 不足以刻画，需要建立有限受控模型的信念状态占用程序（定理3），通过动态规划求解受约束的贝尔曼方程。

  - **T3 – 可判定性边界**：

## 6. 论文的主要结论与发现

1. **T1（符号边界）**：确定性预执行门在 Oracle 下强制执行的策略恰好是安全性且好前缀可被寄存器自动机识别的策略，严格弱于编辑自动机。加替换（sub）不扩大类，但可在有安全重写时降低效用损失。
2. **T2（统计边界）**：对于固定外生实验，精确的安全-效用边界由 Neyman-Pearson ROC 给出；保形校准提供有限样本边际证书（可能空洞地全拦截）。一旦拦截改变后续提议，静态 ROC 不能传递到闭环；必须指定有限受控模型并求解占用优化。
3. **T3（可判定性边界）**：两个可递减计数器使策略非平凡性不可判定；而单调键局部计数器片段（caps、quotas、revoke）在 PSPACE 中可判定，且在线执行时间多项式于当前动作编码和寄存器数量。
4. **实验发现**：静态 ROC 中评判者 AUC 范围为 0.66–0.86，无族系调整后可证明的优越性；校准在 δ=0.05 时退化为全拦截。表示攻击使 11 个评判者中 8 个的漏报率显著增加（增加 0.20–0.60）。闭环实验中，重 3B 门控（78% 拦截）将攻击成功率从 4.7% 降至 0.4%（p=2.2×10⁻⁹），但任务成功率从 25.4% 降至 18.0%；轻 7B 门控（12% 拦截）无统计显著效果。门控也产生了新的攻击（paired discordance 表明存在反馈效应）。

## 7. 优点

- **理论层次清晰**：严格区分 Oracle、统计、闭环三个维度，提供每个维度的精确边界（可强制执行类、ROC 最优性、可判定性），避免了常见混淆。
- **实验设计严谨**：对静态统计采用族系控制的 paired 推断（max-T 区间、Holm 校正）；校准报告 vacuity；攻击实验使用同时套靴区间；闭环测试使用配对 McNemar 检验，避免了独立分组错误。
- **兼顾实用性与理论深度**：T0 片段覆盖了常见的配额、撤销、认证策略，且可判定；在线算法复杂度可行；算法伪代码在附录中给出。
- **明确报告局限性**：作者多次指出实验的特定假设（标签条件交换性、有限攻击模板、未找到受控最优）和理论的前提条件，不自称通用安全。

## 8. 不足与局限

- **实验覆盖不足**：
  - 表示攻击仅使用一个 16-token 后缀，不是通用对抗攻击，未验证 η 是否为上界。
  - 闭环测试只评估了两个手动选择的策略（固定阈值），未求解受控最优，因此不能判断现有门控是否接近理论边界。
  - 三个基准（AgentDojo、InjecAgent、AgentHarm）虽覆盖不同威胁模型，但都是静态指令诊断，未在真实多步应用中评估闭环护栏的完整影响。
- **理论假设较强**：
  - 统计证书要求部署样本与校准样本的标签条件可交换性，这在实践中可能被违反（分布漂移）。
  - 闭环定理要求指定有限的受控抽象，但真实环境的转移核未知且可能过大。
  - 脆弱性校准（Corollary 3）需要已验证的统一裕度 $\bar{\eta}(\rho)$，论文并未提供验证该裕度的可行方法。
- **偏差风险**：
  - 仅使用单个提示模板调用评判者（整数 0-100），不同提示可能改变 ROC（提示敏感性实验仅部分报告，未进行统计调整）。
  - 未进行人工重标定：使用的标签（AgentDojo 的 injected 标签）可能不完全对应安全政策，特别是涉及内容安全的 P1（包含 PII）的监督。
  - 局部 agent（Qwen-7B）攻击成功率较低（4.7%），限制了统计效力；闭环效果可能随更强的攻击而变化。
- **应用限制**：理论主要针对预执行拦截门，不支持缓冲或延迟执行的编辑自动机类策略；替换操作的理论保证需要前缀安全的重写，实际中难以提供；人类升级模型仅作为前缀安全 Oracle 特例，未深入分析。
