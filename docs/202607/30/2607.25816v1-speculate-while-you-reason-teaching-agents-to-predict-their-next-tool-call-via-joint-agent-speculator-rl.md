## 摘要
大型语言模型代理常常花费大量挂钟时间等待工具调用结果。工具调用推测可以通过预测并预执行代理的下一个工具调用（如果预测与代理最终的工具调用匹配）来隐藏这种延迟，但现有的推测器通常是单独的草稿模型或缓存痕迹，与部署的代理自身行为不太对齐。我们识别出这种推测器-代理差距，并表明目标代理本身是一个强大的下一个调用推测器。这指向了一个更简单的设计：将代理和推测器统一在同一个模型中。在本文中，我们引入了自我推测代理，这是一个单一模型，既以代理模式解决问题，又以推测器模式从部分轨迹中预测其下一个工具调用，完全重用前缀KV缓存。为了实现这种双模式代理且不降低性能，我们提出了一种联合代理-推测器强化学习方法，该方法从代理自身的rollout中推导推测目标，并交替进行代理和推测器更新。在代理型搜索问答和对话式工具使用代理任务中，我们的方法将Qwen3-4B的平均下一个工具调用Hit@1从44.1提高到61.2，将Qwen3.5-4B从48.9提高到66.3，同时保持代理任务成功率。

## Abstract
Large language model agents often spend substantial wall-clock time waiting for tool call results. Tool-call speculation can hide this latency by predicting and pre-executing an agent's next tool call if the prediction matches the agent's eventual tool call, but existing speculators are typically separate draft models or cached traces that are poorly aligned with the deployed agent's own behavior. We identify this speculator-agent gap and show that the target agent itself is a strong next-call speculator. This points to a simpler design: unifying the agent and speculator within the same model. In this paper, we introduce the self-speculating agent, a single model that both solves tasks in agent mode and predicts its next tool call from partial trajectories in speculator mode, fully reusing prefix KV cache. To enable this dual-mode agent without degrading performance, we propose a joint agent-speculator reinforcement learning method, which derives speculation targets from the agent's own rollouts and alternates agent and speculator updates. Across agentic search QA and conversational tool-use agentic tasks, our method improves average next tool-call Hit@1 from 44.1 to 61.2 for Qwen3-4B and from 48.9 to 66.3 for Qwen3.5-4B, while preserving agent task success.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：大型语言模型（LLM）代理在执行任务时需要频繁调用外部工具（如搜索引擎、数据库、API 等），但这些工具调用往往涉及远程服务或网络 I/O，导致大量的挂钟时间被浪费在等待工具结果上，而非进行文本生成。这种延迟严重影响代理的响应速度。
- **现有方案及其缺陷**：工具调用推测（tool-call speculation）通过在代理明确发出调用之前预测并预执行未来的工具调用，可以隐藏延迟。然而，现有推测器通常使用外部草稿模型（draft model）或基于历史轨迹的缓存，这些推测器与部署的代理自身行为不一致，存在“推测器-代理差距”（speculator–agent gap）：在相同的中间轨迹条件下，推测器可能会预测出与代理最终调用不同的工具调用，导致预执行结果无法复用。此外，外部推测器还带来额外的模型权重、KV 缓存等系统开销。
- **论文核心思路**：作者识别出目标代理本身已是一个强大的下一个调用推测器，从而提出更简单的设计：将代理和推测器统一在同一模型中，即“自我推测代理”（self-speculating agent），避免部署额外的服务或缓存。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：训练单个 LLM 同时支持两种运行模式：
    - **代理模式（Agent mode）**：按照标准代理流程生成推理、工具调用、观察和最终答案。
    - **推测器模式（Speculator mode）**：接收中间轨迹加上固定推测后缀（speculation suffix），直接预测下一个结构化的工具调用（包括工具名称和参数）。
    - 两种模式共享模型参数和前缀 KV 缓存，推理时仅需在推测后缀处分支解码候选调用，无需额外模型或缓存。
- **关键技术细节**：
    - **推测目标构建**：从当前策略生成的代理 rollout 中，在每个工具调用边界取前缀 \( h_t \)，附加固定推测后缀 \( s_{sp} \)，以代理实际的下一个调用 \( a_t \) 为标签，形成 on-policy 的推测训练数据。
    - **奖励设计**：
        - 工具名称匹配奖励 \( R_{\text{name}} = \mathbf{1}[\hat{n}_t = n_t] \)。
        - 参数匹配奖励 \( R_{\text{args}} \)：对目标参数的每个键计算 macro token-F1，缺少预测键得 0，多余键不计分。
        - 最终推测奖励 \( R_{\text{sp}} = R_{\text{name}} \cdot R_{\text{args}} \)。
        - 代理任务奖励 \( R_{\text{ag}} \) 基于最终答案与 ground-truth 的比较。
    - **联合 Agent-Speculator 强化学习**（算法 1）：
        - 每次迭代采样查询批次，生成 \( G_{\text{ag}} \) 条 agent rollout，从中提取推测样本，再为每个推测样本生成 \( G_{\text{sp}} \) 条 speculator rollout。
        - 按照固定交替调度 \( m(k) \) 切换优化目标：4 步 agent 更新 + 8 步 speculator 更新。
        - 两个模式均使用 DAPO 风格的分组策略优化（Grouped Policy Optimization）。
    - **稳定训练技巧**：
        1. **SFT 热身**：RL 前，用成功轨迹（agent 示例）和部分轨迹+推测后缀（speculator 示例）的混合数据进行监督微调，让模型学会正确输出格式。
        2. **优化器状态重置**：每次模式切换时重置优化器状态，避免动量/自适应统计量在两种不同目标间干扰。
        3. **代理奖励惩罚**：对重复无意义的工具调用施加惩罚。

## 6. 主要结论与发现

- **自我推测代理显著提升推测准确性**：Qwen3-4B 平均 Hit@1 从 SFT 的 44.1 提高到 RL 的 61.2（+17.1）；Qwen3.5-4B 从 48.9 提高到 66.3（+17.4）。所有数据集均呈现一致提升。
- **任务成功率保持稳定**：平均成功率 Qwen3-4B 从 26.6 微升至 27.7；Qwen3.5-4B 从 49.2 提升至 50.6，无系统性退化。
- **外部推测器不仅增加开销，且预测能力弱于自我推测**：较小说模型需要额外显存和更长时间，但 Hit@1 远低于目标代理自身推测。例如 Qwen3-4B 自我推测 Hit@1 为 29.1，而最强外部推测器 Qwen3-1.7B 仅为 18.6。
- **联合 RL 训练需配合稳定技巧**：SFT warmup、优化器重置、长块交替调度对训练稳定性和最终性能至关重要。

## 7. 优点

- **方法创新性**：首次提出将代理和推测器统一为同一模型的“自我推测代理”，从根本上消除推测器-代理差距，并简化系统架构。
- **训练设计巧妙**：从代理自身 rollout 中 on-policy 构建推测目标，使用联合交替 RL 优化，既提高推测准确性又保持任务性能。
- **系统级优势**：完全复用前缀 KV 缓存，无需额外模型权重或缓存，降低内存和计算开销，更适合资源受限场景。
- **稳定技术有效**：SFT warmup、优化器重置、交替调度等技巧经过充分验证，可推广到类似双目标 RL 场景。

## 8. 不足与局限

- **应用限制**：仅适用于**只读工具**（如搜索、检索、数据库查询），不适用于会改变外部状态（如下单、发送消息）的工具。对于状态更改的调用需要额外保护机制（如试运行、事务回滚或限制在只读阶段）。
- **实验覆盖有限**：
    - 仅评估了 4B 规模模型（Qwen3-4B 和 Qwen3.5-4B），更大模型可能具有不同的优化动态和推测器-代理差距。
    - 仅覆盖两种任务家族（搜索 QA 和对话式工具使用），未扩展到代码执行、网页导航、多代理工具等更广泛场景。
- **跨域泛化**：推测能力可跨域转移，但任务成功率下降，说明域特异性推理仍需匹配域训练。
- **推测奖励设计**：使用的 macro token-F1 在参数接近但并不完全匹配时仍能提供部分信号，但与部署时的精确匹配要求之间存在 gap，可能导致训练与评估目标不一致。
