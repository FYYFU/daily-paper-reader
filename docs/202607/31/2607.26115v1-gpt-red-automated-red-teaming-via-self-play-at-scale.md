## 摘要
我们介绍了\textbf{GPT-Red}，一种经过训练的自动化红队测试智能体，旨在发现针对前沿LLM的新颖提示注入攻击。该模型的目标是评估并提升我们生产系统的鲁棒性。为此，我们使用它对GPT-5.6进行对抗性训练，这是迄今为止我们对提示注入最具鲁棒性的模型。为了创建GPT-Red，我们设计了一种可扩展的自我对弈算法，其中模型被任务要求攻击一组同时训练的防御者智能体的多样化群体。我们利用与我们一些最大的强化学习后训练运行相当的算力，在逼真的红队测试环境中训练该模型，使其成为有史以来记录中最大规模的LLM安全训练运行。GPT-Red擅长红队测试：它能可靠地攻破我们过往的模型（直至GPT-5.5），比人类红队成员发现更多成功的攻击，并能泛化到未见过的环境、防御者模型和测试框架中。未来，我们预计随着我们提升每个新GPT模型的鲁棒性，它反过来将为\textit{更强}的红队智能体提供更好的学习信号，从而开启自我改进的飞轮效应。

## Abstract
We introduce \textbf{GPT-Red}, an automated red-teaming agent that is trained to discover novel prompt injection attacks against frontier LLMs. The goal of this model is to evaluate and improve the robustness of our production systems. To this end, we use it to adversarially train GPT-5.6, our most robust model to prompt injections to date. To create GPT-Red, we design a scalable self-play algorithm where the model is tasked with attacking a diverse population of simultaneously-trained defender agents. We train the model on realistic red-teaming environments using compute on the same scale as some of our largest RL post-training runs, making it the single-largest LLM safety training run ever documented. GPT-Red excels at red-teaming: it reliably breaks our past models up to GPT-5.5, it finds more successful attacks than human red-teamers, and it generalizes to held-out environments, defender models, and harnesses. In the future, we expect that as we improve the robustness of each new GPT model, it will in turn will provide better learning signal for \textit{even stronger} red-teamer agents, thus unlocking a self-improvement flywheel.

## 1. 核心问题与整体含义

- **研究背景**：随着 LLM 在 agentic 场景中的广泛部署，模型必须能够抵御针对其行为的对抗性操纵，尤其是提示注入（prompt injection）和内容策略越狱（jailbreak）。
- **现有方法的不足**：RL 对抗训练通常依赖人工红队、提示 LLM 或真实攻击样本，这些数据规模有限，模型容易过拟合特定攻击模式，且对自适应对手（adaptive adversaries）的鲁棒性不足。攻击面随模型能力和用例扩展而增大，手工数据难以跟上。
- **核心问题**：如何自动化地、大规模地生成高质量、多样且有效的对抗样本，以持续评估和提升前沿 LLM 的鲁棒性？
- **本文方案**：提出 **GPT-Red**，一个专门训练的自动化红队智能体，通过**大规模自我对弈（self-play）** 同时训练攻击者与多个防御者，使其能够发现新颖的提示注入攻击，并用于对抗训练生产模型 GPT-5.6。
- **整体含义**：GPT-Red 不仅是一个红队工具，更代表了一种“安全飞轮”——更强的防御模型为更强的红队智能体提供训练信号，反之亦然，从而实现模型安全性的持续自我改进。

## 2. 方法论

### 2.1 核心思想

- 采用**自博弈强化学习**：攻击者（attacker）与一组防御者（defender）同时训练。
  - 攻击者奖励：引发有效失败（如成功提示注入或策略违反）。
  - 防御者奖励：抵抗攻击并完成原始任务。
- 通过三个维度的扩展实现规模化和有效性：
  - **推理时计算扩展**：为攻击者提供 agentic harness，包括 `defender_model` 工具，使其能与防御者交互式迭代、细化攻击。
  - **环境多样性**：将现有能力任务转换为多种真实的红队 RL 环境。
  - **训练计算扩展**：在大规模 RL 训练中同时训练攻击者与防御者种群。

### 2.2 威胁模型（Threat Model）

- 攻击者只能修改**单个工具响应或非特权文件**（如搜索结果、邮件内容、本地文件），不能修改特权内容（如 `AGENTS.md`）。
- 攻击者具有黑盒查询防御者的权限，查询次数有限，可观察防御者完整轨迹及 token 对数似然。
- 采用程序化/LLM 检查自动拒绝非法攻击，保证攻击在真实威胁模型下合法。

### 2.3 推理时扩展：defender_model 工具

- 攻击者可通过终端工具创建攻击文件，用 `defender_model` 工具提交攻击路径，并获得防御者的轨迹、反馈和判定。
- 该工具支持在单次 rollout 内进行结构化搜索（如分支、变体测试、代码生成攻击）。
- 实验表明，相比 best-of-N 独立采样，agentic harness 在相同查询预算下取得更高攻击成功率。

### 2.4 自博弈训练算法

每轮迭代包含以下步骤：

1. 采样一个 RL 环境：对话、文件系统初始状态、一个防御者模型。
2. 选择上下文相关的攻击插入点（通常是工具调用）和攻击目标。
3. 攻击者进行 rollout，可调用 `defender_model` 探测，最终提交攻击。
4. 验证攻击合法性与环境有效性，非法则奖励为 0。
5. 将攻击插入到防御者 rollout 的预定义位置，恢复防御者轨迹。
6. 计算环境特定奖励（通常是攻击者成功与防御者任务完成的不对称检查）。
7. 用 (轨迹, 奖励) 对更新攻击者和防御者。

### 2.5 多防御者训练

- 初步实验发现单防御者容易导致攻击者模式崩溃；同时训练多个（如 9 个）强防御者可迫使攻击者探测各模型的弱点，生成更多样、更专化的攻击。

### 2.6 RL 环境构建

- **直接提示注入**：扩展 IH-Challenge，攻击者可编辑低优先级消息，使用可验证奖励（如不泄露 PIN、正则替换、结构化解析）。
- **间接提示注入**：
  - 浏览、深度研究：攻击者可编辑单个网站文本。
  - 第三方连接器（Gmail、日历）：攻击者可编辑工具响应中的邮件/日历内容。
  - 通用函数调用（FC）：攻击者可覆盖单个工具输出。
  - Agentic 编码：攻击者可编辑本地文件或工具调用结果。
  - 多模态场景：攻击者使用图像生成 API，生成包含恶意指令的图片（如屏幕截图中的横幅广告、伪造的收据/文档）。
- **安全拒绝越狱**：将良性对话引导至恶意请求（如化学武器合成），通过 rubric 打分，并过滤掉“仅要求表面转换”或“不像真实用户对话”的攻击。

### 2.7 模型训练

- 用 GPT-5.5 初始化 GPT-Red，在全部环境上对抗包括 GPT-5.5 在内的过去防御者种群训练，同时混合标准 RL 后训练环境以保持通用能力。

- **通用能力保持未深入探讨**：论文提到混合标准 RL 后训练环境以保持通用能力，但没有系统分析对抗训练可能给通用表现带来的退化程度，也没有讨论在多大比例的安全数据下会出现能力的“遗忘”或“权衡”。
- **奖励函数仍依赖人工设计**：尽管攻击和防御由 RL 自动推进，但环境构建、防御者判定规则、合法性检查和 reward 信号的设计仍需大量人工干预，尤其是闭环环境（如自动售货机）中的评估仍需要人工确认攻击是否真实成功。
- **白盒/灰盒假设的适用范围有限**：GPT-Red 拥有防御者的 token 对数似然和完整轨迹反馈，这在 API 部署的商用模型中通常不可获得；论文提到 GPT-5.5 即使有 harness 也无法达到同等攻击效果，说明模型能力本身仍是关键，但白盒信息的贡献量未进行严格剥离。
- **攻击场景偏组合型而非复杂规划**：虽然内部数据泄露任务进行了长时间跨文件侦查与多步骤攻击，但论文对攻击者能否在真实软件工程任务中进行更高阶的推理与长期规划没有做充分评估。
- **未来工作**：
  - 扩展到多模态、语音、网页操作等更复杂的 agentic 环境；
  - 研究更高效的训练方法，以降低大规模自博弈所需算力；
  - 增强攻击者内存/反思能力，使攻击者在更长时间跨度内计划和适应；
  - 将防御者种群扩展到开源模型与第三方系统，提升泛化性；
  - 进一步探索“安全飞轮”的可持续性与可能的安全悖论（更强的红队工具被滥用时的风险）。

## 8. 个人备注 / 关键价值判断

- **技术路径具有前沿代表性**：将自博弈从博弈论和围棋等场景迁移到 LLM 安全战线，并用交互式 agentic harness 把推理时计算引入攻击搜索，思路清晰且工程完成度高。
- **“规模驱动安全”的佐证**：论文暗示 LLM 安全的突破不一定来自新的架构或机理，而可能来自更大规模的安全 RL 训练——这为后续安全研究提供了一种可复现的范式参考。
- **评估闭环的内外不对等是最大隐忧**：几乎所有关键评估都在 OpenAI 内部环境完成，且模型对比只涉及少量基线；外部研究者很难独立验证“最强大自动化红队”的绝对论断。未来若能开放部分场景、预训练检查点或评估沙盒，将显著提升该工作的学术价值。
- **安全与攻击的双刃性**：GPT-Red 这类系统本身就是一本“攻击手册”，OpenAI 需要仔细管理其发布策略和使用范围，避免被恶意利用。

## 9. 结论

GPT-Red 通过大规模自博弈将自动化红队从“数据收集 + 提示词变体”推进到“动态演化的对抗性智能体”阶段，在提示注入和越狱攻击的发现与防御者鲁棒性提升两方面均取得显著成果。其核心价值在于证明了安全能力可以通过自我博弈持续演化，为下一代 LLM 的对抗训练提供了一个现实可行的规模化路径。尽管在可复现性、评估开放性和奖励设计上仍有不足，GPT-Red 仍构成了 LLM 安全领域的一次重要里程碑式实践。
