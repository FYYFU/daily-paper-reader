## 摘要
自主智能体越来越需要对外部系统产生不可逆的影响——转移资金、写入持久存储、驱动硬件。现有的智能体框架（ReAct、Reflexion、MCP）在基准测试上优化任务成功率，很少关注不可逆副作用的安全性。我们将其中一个场景——跨公共账本的价值转移——形式化为一个由（钱包、链、地址、协议）索引的四维空间中的状态转换，并利用该形式化体系来陈述并证明我们称之为“执行保真度”的保证：在允许规划器错误映射、模糊结果、重试、至少一次投递以及委托非人类调用者的故障模型下，会话在账本上实现的效果要么什么都没有，要么恰好是呈现给用户的转换，且恰好一次。该定理刻意不声称所呈现的转换与用户意图一致——任何运行时层都无法决定这一点——但它将这个无界问题限制为对有限对象的单一谓词，这正是使得预览成为充分控制而非形式上的程序的原因。七个安全不变量，从保真度条件推导而来而非凭经验枚举，履行了这一保证。实证上，在受控的N=60对抗性测试套件中，该技术栈在两种写激进的后端模型上比朴素ReAct基线的通过率提高了约74个百分点，但在写保守的后端模型上仅提高了约3个百分点——这表明对智能体安全技术栈的单一模型评估几乎无法证伪。该系统已部署；跨8条链的108次生产写入操作支撑了故障分类。虽然评估环境是公共账本，但该形式化体系和不变量适用于作用于不可逆外部状态的任何概率智能体。

## Abstract
Autonomous agents are increasingly asked to produce irreversible effects on external systems - transferring funds, writing to durable storage, actuating hardware. Existing agent frameworks (ReAct, Reflexion, MCP) optimize task success on benchmarks and give little attention to the safety of irreversible side-effects. We formalize one such setting, movement of value across public ledgers, as state transitions in a four-dimensional space indexed by (wallet, chain, address, protocol), and use that formalism to state and prove a guarantee we call execution fidelity: under a fault model admitting planner mis-mapping, ambiguous outcomes, retries, at-least-once delivery, and delegated non-human callers, a session's realized effect on the ledger is either nothing at all or exactly the transition that was rendered to the user, exactly once. The theorem deliberately does not claim that the rendered transition matches the user's intent - no runtime layer can decide that - but it confines that unbounded question to a single predicate over a finite object, which is what makes a preview a sufficient control rather than a formality. Seven safety invariants, derived from the fidelity condition rather than enumerated from experience, discharge the guarantee. Empirically, on a controlled N=60 adversarial suite the stack lifts pass rate by ~74 percentage points over a naive-ReAct baseline on two write-aggressive backing models, but by only ~3 points on a write-cautious one - evidence that single-model evaluations of agent safety stacks are close to unfalsifiable. The system is deployed; 108 production write operations across 8 chains back the failure taxonomy. Although the evaluation setting is public ledgers, the formalism and invariants apply to any probabilistic agent acting on irreversible external state.

- **具体风险场景**：以公共账本（公链）上的价值转移为例，用户在自然语言中要求"把我所有 USDC 存入 Hyperliquid"或"把 200 USDT 换成 BTC"，智能体需要处理链选择、合约授权、跨链桥、RPC 一致性等复杂环节。若仅将签名和广播工具朴素地包装进智能体，会可靠地产生"烧钱式"失败模式。
- **核心洞察**："智能体做用户想做的事"这一诱人答案在运行时层不可判定（自然语言请求与事务元组是否匹配无法由运行时判断）。论文退而求其次，提出一个更窄但更有用的保证——**执行保真度（Execution Fidelity）**，将无界语义问题压缩为对有限对象的单一谓词检查。
- **现实案例支撑**：论文观察到三类真实故障——RPC 层面的"幻影成功"（返回哈希后被撤回）、LLM 层面的"陈旧上下文漂移"（过时结论压制重新查询）、交易所 API 层面的"文档原子性漂移"（声称为原子的 cancel-and-replace 只执行了一半）。其中一次因误报失败后的重试造成了 200 USDT 的重复交易，造成真实资金损失。

### 二、方法论：核心思想、关键技术细节

#### 2.1 四维状态空间形式化

- **状态空间定义**：定义状态 s 为函数 s: W × C × A × P → Z≥0，其中 W 为助记词（钱包）集合、C 为链集合、A 为链上地址集合、P 为协议（代币/合约/链下账户）集合。余额以协议最小单位（wei、satoshi、lamport 等）的非负整数表示。
- **状态转移（Transition）**：定义为偏函数 τ: S → S，满足两个形式约束：**守恒性**（在守恒类 K 上的聚合余额变化 = 费用 - 铸/销毁增量）和**签名授权**（任何余额减少的坐标必须有来自对应钱包派生的有效签名）。
- **四维空间的必要性**：八个转移原语（Transfer、Swap、Bridge、Deposit、Withdraw、Trade、Intra-Exchange、Contract）各自在四个轴上移动不同的坐标组合，任何一个轴都不能省略。钱包维度 W 尤其重要——它虽从不移动，但错误选择钱包是第二常见的失败类，三轴模型无法表达该错误。
- **组合与计划**：有限链 π = τn ◦ ... ◦ τ1 构成计划，守恒与签名条件逐坐标复合。

#### 2.2 故障模型与执行保真度

- **会话（Session）**：一次完整管线——自然语言请求 u、智能体承诺并渲染的单一转移 τp（预览）、以及后续执行。real(σ) 为会话导致的链上转移多重集合（多重集而非集合，以表达重复执行）。
- **六类故障（F1–F6）**：F1 意图错映射（无界，运行时不可判定）、F2 前状态漂移、F3 结果歧义、F4 重新发起、F5 重复投递、F6 非人类调用者。
- **执行保真度定义**：real(σ) ∈ {∅, {τp}}——要么什么都没发生，要么恰好发生一次且恰好是渲染给用户的那个转移。
- **定理证明**：通过三分支案例分析证明——(a) 非渲染转移不能执行（Invariant 1、5）；(b) 不能执行两次（Invariant 3、4、6、7）；(c) 不能执行"派生但不同"的转移（Invariant 2）。推论 1 指出：唯一能产生意外不可逆效果的故障是 F1。

#### 2.3 七个安全不变量（从保真度条件推导，而非经验枚举）

| # | 不变量 | 层级 | 排除的违规分支 |
|---|--------|------|---------------|
| I1 | 确认门（Confirm gate）：确认前不派生签名密钥 | 执行器本地 | (a) 未渲染执行 |
| I2 | 前状态充分性：广播前对 L1 链上余额做真值检查 | 执行器本地 | (c) 广播时不适用 |
| I3 | 后状态可观测性：探测超时报告"不确定"而非"失败" | 执行器本地 | (b) 虚假失败报告 |
| I4 | 无幻影成功：未验证上链的哈希不得声称成功 | 执行器本地 | (b) 虚假成功报告 |
| I5 | 作用域委托：调用者须持覆盖转移作用域的授权谓词 | 跨层 | (a) 无资格调用者 |
| I6 | 计划级重试安全：重发前须正向确认前序转移未发生 | 计划级 | (b) 规划器重发 |
| I7 | 幂等意图接收器：对至少一次通道做去重 | HTTP 接收器 | (b) 通道重投 |

- **关键实现细节**：
  - I1 的确认门采用两阶段 write 工具（confirm=false 返回预览，confirm=true 释放密钥）。论文坦承实际部署中此门曾被类型强制绕过——MCP 将布尔参数序列化为字符串 "false"，Python 非空字符串真值性将其提升为 True。
  - I2 必须绕过最终一致的索引器缓存，直接读取 L1 RPC balanceOf；默认 s ∈ dom(τp) 在广播时检查而非规划时。
  - I3/I4 采用 ≤12 秒轮询窗口，超时返回 UNCERTAIN（含区块浏览器 URL）而非 FAILED。
  - I6 针对 avatar 层（无人值守的定时/触发代理），必须通过 I2 同路径查真值后确认不存在的才可重试。
  - I7 采用 H(sender_id, request_bytes) 哈希 + 30 秒滑动窗口去重，命中时原样重放已记录响应。

#### 2.4 系统架构

- **cryptitalk-wallet**：三层系统——执行器（Executor，钱包）、化身（Avatar，用户安装的持久代理）、分析器（Analyst，只读数据服务），通过 agent SDK 和 MCP 胶合，跨层使用委托令牌。
- **安全模型**：Avatar 持有绑定特定 (user, avatar, Σ) 三元的长期委托令牌，走与人类会话令牌相同的认证中间件代码路径，无特权后门。

### 六、主要结论与发现

1. **执行保真度可证明可实现**：在 F1–F6 故障模型下，七个不变量足以保证会话效果为 ∅ 或 {τp} 之一；唯一能产生意外不可逆效果的故障仅剩 F1（意图错映射）。
