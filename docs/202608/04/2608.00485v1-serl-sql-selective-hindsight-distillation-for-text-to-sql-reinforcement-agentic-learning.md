## 摘要
近年来，Text-to-SQL系统越来越依赖于多轮交互、执行反馈和强化学习。然而，大多数现有方法仅将执行正确性作为轨迹级奖励，这为识别导致成功或失败的SQL决策提供的指导有限。我们提出SERL-SQL，一种面向多轮Text-to-SQL智能体的选择性基于执行的强化学习框架。SERL-SQL采样在策略的SQL交互轨迹，并使用仅训练用的教师模型根据执行反馈重新为学生动作打分。由此产生的师生似然差距被转换为有界的、掩蔽的权重，仅在SQL和工具操作令牌上重新加权GRPO优势。这样，任务奖励保持了优化方向，而执行回溯提供了局部信用分配。在BIRD、Spider和跨域基准上的实验表明，SERL-SQL取得了有竞争力的性能，在BIRD-Dev上达到76.56%的执行准确率，在Spider-Test上达到89.92%。此外，我们基于奖励的选择策略接近oracle Best-of-N上界，并持续优于基于一致性的选择，表明SERL-SQL生成的候选方案质量高，可被轻量级基于执行的奖励可靠地识别。我们的代码将在https://github.com/Ffunkytao/SERL-SQL发布。

## Abstract
Recent Text-to-SQL systems increasingly rely on multi-turn interaction, execution feedback, and reinforcement learning. However, most existing methods use execution correctness only as a trajectory-level reward, which provides limited guidance for identifying the SQL decisions responsible for success or failure. We propose SERL-SQL, a selective execution-grounded reinforcement learning framework for multi-turn Text-to-SQL agents. SERL-SQL samples on-policy SQL interaction trajectories and uses a training-only teacher to re-score student actions with execution feedback. The resulting teacher--student likelihood gap is converted into bounded, masked weights that reweight GRPO advantages only on SQL and tool-action tokens. In this way, task rewards preserve the optimization direction, while execution hindsight provides localized credit assignment. Experiments on BIRD, Spider, and cross-domain benchmarks show that SERL-SQL achieves competitive performance, reaching 76.56% execution accuracy on BIRD-Dev and 89.92% on Spider-Test. Moreover, our reward-based selection strategy closely approaches the oracle Best-of-N upper bound and consistently outperforms consistency-based selection, showing that SERL-SQL produces high-quality candidates that can be reliably identified by lightweight execution-grounded rewards. Our code will be released at https://github.com/Ffunkytao/SERL-SQL.

### 1. 核心问题与研究动机

- **背景**：Text-to-SQL 任务近年从单次 SQL 生成转向多轮智能体式数据库交互，系统通过 schema 定位、SQL 生成、执行、验证、修订和选择等步骤，利用数据库执行反馈提升性能。代表性工作包括 Agentar-Scale-SQL、Arctic-Text2SQL-R1、MARS-SQL 等。
- **核心问题**：现有方法大多只将执行正确性作为**轨迹级（trajectory-level）奖励**，即同一条轨迹中的所有 token（包括关键 SQL 决策、推理 token、格式 token）都获得相同的优势值。这种粗粒度反馈无法定位导致成功或失败的具体 SQL 决策，造成信用分配（credit assignment）模糊。
- **关键洞察**：执行反馈（如运行时错误、空结果、结果不匹配等）不仅可作为结果奖励，还可作为**训练时的特权事后信息（hindsight）**，帮助判断哪些 SQL 决策导致了失败。SERL-SQL 利用这一洞察，在不泄露特权信息到推理阶段的前提下，实现细粒度的、局部的信用分配。

### 2. 方法论

#### 2.1 总体框架（四阶段流水线）

1. **Schema 接地（Schema Grounding）**：将完整数据库 schema 压缩为紧凑的、包含关键值的子集，为后续 SQL 生成提供价值感知的数据库上下文。
2. **多轮 SQL 智能体 Rollout**：学生策略通过"思考→行动→观察"循环，采样多条交互轨迹，并由分层奖励验证器给出轨迹级奖励。
3. **选择性执行事后教师（Selective Execution-Hindsight Teacher）**：仅训练时使用的教师模型，在观察到执行反馈的背景下重新为学生动作打分。
4. **事后引导的优势重加权（Hindsight-Guided Advantage Reweighting）**：将师生对数似然差转换为有界的掩码权重，只对 SQL 和工具动作 token 的 GRPO 优势进行重新加权。

#### 2.2 关键技术细节

- **轨迹奖励定义**（公式 12）：

```
Rn = +1（轨迹有效且 SQL 正确）
     0（轨迹有效但 SQL 错误）
    -1（轨迹无效）
```

- **GRPO 优势计算**（公式 2）：对同一问题的 N 条轨迹奖励做组内标准化得到轨迹级优势 An。
- **师生对数似然差距**（公式 16）：

```
Δt,i = log πT(yt,i | ht, yt,<i, c_ex_t) − log πθ(yt,i | ht, yt,<i)
```

  正值表示该 token 在执行事后信息下变得更可能，负值表示不被执行反馈支持。

- **有界符号感知权重**（公式 17）：

```
wt,i = clip(exp(sgn(An) · sg[Δt,i]), w_min, w_max)
```

  其中 w_min = 1−εw，w_max = 1+εw。轨迹优势的符号用于对齐教师证据与奖励方向：正优势轨迹中，事后支持的 token 被强化；负优势轨迹中，事后不支持的 token 被抑制。

- **选择性动作掩码**（公式 18）：非动作 token 保持原始 GRPO 权重，仅 SQL 和工具动作 token 接受事后引导的重新加权。

- **事后衰减系数**（公式 19）：

```
Ât,i = An[(1−αk) + αk·w̄t,i]
```

  训练早期 αk 较大，依赖事后信息改善信用分配；训练后期 αk 衰减，回归奖励驱动方向，降低对特权教师的依赖。

- **最终目标函数**（公式 20）：使用裁剪的 GRPO surrogate 加 KL 正则项，任务奖励决定优化方向，执行事后信息只调节更新的局部性和幅度。推理时教师被移除，学生策略独立部署。

### 6. 主要结论与发现

1. **性能表现**：SERL-SQL 在 BIRD-Dev 上 32B 模型达到 **76.56%（与 oracle Best-of-N 77.84% 仅差 1.28 个百分点）**，Spider-Test 上 14B 模型达到 **89.92%**，Spider-DK 上 32B 达到 **82.21%**。
2. **细粒度信用分配有效**：执行事后信息经过掩码、裁剪、符号感知和衰减处理后，显著优于简单轨迹级 GRPO 和朴素师生蒸馏。
3. **奖励选择优于一致性选择**：reward_max 选择策略持续优于多数一致性（majority voting），说明执行接地奖励比一致性更能识别高质量候选。
4. **Schema 接地最重要**：在消融实验中，去除 schema 接地导致最大性能下降（74.95% → 66.42%），表明紧凑、语义对齐的 schema 上下文是有效信用分配的前提。
5. **事后信息应局部化**：即时观察（immediate observation）优于完整观察（full observation），说明反馈应因果对齐当前 SQL 动作，过长反馈反而模糊 token 级归属。
6. **主要剩余错误**：JOIN 构建（29.1%）和语义误解（24.6%）是主要瓶颈，表明多表推理和细粒度值接地仍需改进。

### 7. 方法亮点

- **设计巧妙的信用分配机制**：将粗粒度轨迹奖励与细粒度执行事后信息有机整合，任务奖励保留优化方向，事后信息只调整更新幅度和局部性，两者互不干扰。
- **训练-推理不对称架构**：教师只在训练时使用特权执行反馈，推理时完全移除，避免了信息泄漏和部署开销。
- **有界、符号感知、选择性掩码三重防护**：权重裁剪限制教师信号强度，符号感知保证不偏离奖励方向，选择性掩码防止信用扩散到非执行 token。
- **课后衰减机制**：训练后期逐步降低事后信息依赖，既利用了前期精细信用信号的加速效果，又避免了对教师特权信息的过度依赖。
- **实验分析全面**：不仅报告了性能数字，还从轨迹质量分布、选择策略对比、错误类型分布、事后信息来源等多角度深入剖析了方法的行为特性。
