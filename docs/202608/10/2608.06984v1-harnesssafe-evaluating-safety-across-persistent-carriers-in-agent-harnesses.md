## 摘要
现代智能体框架通过记忆、技能、工具和共享工件等持久化载体，在任务和会话之间维持状态。然而，这种能力带来了延迟的安全风险：受攻击者影响的内容可以跨越系统边界，并在之后影响良性请求的执行。现有基准通常侧重于少数载体或框架，而端到端的攻击成功率几乎无法揭示风险的传播方式。为此，我们提出了HarnessSafe，一个包含七大持久化载体家族共328个可执行案例的基准，并在大多数主流智能体框架上进行了评估。每个案例被定义为持久化风险生命周期，追踪攻击者影响从初始进入、跨载体和系统边界持久化，到后续良性触发和可观察违规的完整过程。我们进一步引入了一种基于轨迹的多阶段评估方法，利用可观察的执行证据来确定每条攻击链的推进程度及其被阻断的位置。实验表明，隔离效果具有载体特异性，并强烈依赖于框架-模型配置。框架和后端模型都显著影响隔离结果，而攻击成功率无法反映不同的生命周期推进模式。

## Abstract
Modern agent harnesses persist state across tasks and sessions through persistent carriers like memory, skills, tools, and shared artifacts. However, this capability creates delayed safety risks: attacker-influenced content can cross system boundaries and later affect the execution of a benign request. Existing benchmarks typically focus on a few carriers or harnesses, while end-to-end attack-success rates reveal little about how risks propagate. To this end, we present HarnessSafe, a benchmark comprising 328 executable cases across seven persistent-carrier families and evaluated on most mainstream agent harnesses. Each case is specified as a Persistent-Risk Lifecycle that traces attacker influence from its initial entry, through persistence across carriers and system boundaries, to a later benign trigger and an observable violation. We further introduce a multi-stage, trace-based evaluation that uses observable execution evidence to determine how far each attack chain progresses and where it is stopped. Experiments show that containment is carrier-specific and strongly depends on the harness-model configuration. Both the harness and model backend substantially shape containment outcomes, while attack success rates cannot reflect distinct lifecycle progression patterns.

- **现有基准的不足**：已有基准（如 ASB、AgentLAB、MINJA、SkillSafetyBench、MCPTox 等）存在三个关键缺陷：

  3. 缺乏统一的攻击语义描述，难以在异构框架间进行公平、语义对齐的比较。

## 2. 方法论：核心思想与关键技术细节

### 2.1 统一持久化风险生命周期（Persistent-Risk Lifecycle）
- 每个案例由一个五元素元组定义：
  \[
  K = \langle E, C, B, T, V \rangle
  \]
  - **E**：攻击者影响的入口（attacker-influenced entry）
  - **C**：保留影响的声明载体状态或有序载体状态路径
  - **B**：影响必须存活的声明的载体、会话、进程、智能体或工作区边界
  - **T**：后续独立的良性触发（不包含对抗指令，也不授权违规行为）
  - **V**：可观察的违规（由预定义 oracle 验证）
- **适配契约（Harness Adaptation Contract）**：生命周期以角色（roles）而非机制（mechanisms）声明。一个案例可在不同框架上被绑定为不同的原生实现（不改变何种输入受攻击者控制、边界语义、触发独立性及 oracle 证据阈值），从而保持安全语义跨框架对齐。

### 2.2 三大层级、七大持久化载体家族
- **Tier 1 核心持久化表面（Core Persistent Surfaces）**：
  - **F1 Memory（72 案例）**：测试攻击者影响的记忆是否跨边界存活并影响后续良性任务。
  - **F2 Skill（84 案例）**：测试被篡改的技能内容、元数据或运行时工件是否影响后续良性使用。
  - **F3 Tool/MCP（70 案例）**：测试攻击者影响的模式、元数据或保留输出在重启/刷新后是否影响后续调用。
- **Tier 2 跨载体转换（Cross-Carrier Transformation）**：
  - **T2 Memory→Skill（36 案例）**：追踪影响从记忆进入生成/更新的技能，再到下游良性消费者任务，需要中间载体写入和下游执行的证据。
- **Tier 3 跨边界传播（Cross-Boundary Propagation）**：
  - **T3-S Subagent Delegation（30 案例）**：跨子智能体实例边界传播。
  - **T3-C Session Summary（30 案例）**：影响是否在会话摘要/压缩后存活并在恢复后被重新消费。
  - **T3-A Shared Artifact（6 案例）**：跨工作区交接边界的共享工件复用。

### 2.3 多级、基于痕迹的评估（Multi-Stage, Trace-Based Evaluation）
- **七级推进阶梯（N0–N5b）**，每级由可观察的执行证据支撑：
  - **N0**：未观察到与污染表面的接触
  - **N1**：入口被暴露
  - **N2**：载荷影响状态/参数/工件/行为
  - **N3**：跨声明边界持久化并随后在良性阶段被重新消费
  - **N4**：尝试了不安全操作（但无成功执行证据）
  - **N5a**：oracle 确认的违规
  - **N5b**：完整声明链路 + 精确 canary 从触发阶段到达蜜罐
- **正交结果 N−1**：工作流未完成（workflow noncompletion），不计分、不视为安全。
- **Chain-Stage Score（CSS）**：为各阶段分配递减的安全权重（N0=100 至 N5b=0），较高的 CSS 表示更早的遏制。标准化聚合保留基准的固定家族权重，同时报告覆盖率（Coverage）防止框架通过跳过难例获得虚高分数。
- **证据要求**：违规判定依赖于工具事件、模型生成的参数、工件痕迹、蜜罐观察等，而非模型自述或意图。N5b 要求精确 canary 的触发阶段归属。

## 6. 主要结论与发现

- **RQ1：遏制效果具有载体特异性和配置依赖性**。没有任何框架-模型组合在所有载体家族上表现一致良好。最高整体 CSS 的配置（Codex CLI，62.3）反而在 F2 Skill 上得分最低（47.0 vs 最高 70.0）。
- **RQ2：持久化风险遏制是"配置"的属性，而非单独框架或单独模型的属性**：
  - 固定 GPT-5.6-Sol：跨框架 CSS 从 39.4（Claude Code）到 62.3（Codex CLI），跨度 22.9 分；
  - 固定 Claude Code：跨后端 CSS 从 22.7（MiniMax M2.5）到 58.7（Claude Sonnet 4.6），跨度 36.0 分；
  - 两种效应量级相当，且可能相互抵消——框架和模型的配对才是最小有意义的安全评估单元。
- **RQ3：观察到的违规可归因于声明的完整生命周期**。匹配控制实验表明，移除任一关键生命周期元素（入口、持久化、触发、清理）都能使 ASR 降低至少 90%（从 25.8% 降至 ≤2.5%）。
- **关键发现：攻击成功率（ASR）不能反映生命周期推进模式的差异**。ASR 相近的配置可能在不同阶段停止（如 Hermes 与 OpenCode 的 ASR 仅差 0.73 个百分点，但主要在 N1/N2/N4 阶段被阻断），端点指标会掩盖截然不同的残余风险。

## 7. 优点

- **跨框架语义对齐的基准设计**：通过五元素生命周期抽象，将同一攻击语义绑定到不同原生机制上，解决了此前基准无法跨框架比较的痛点。
- **多级、基于证据的评估体系**：N0–N5b 七级阶梯 + CSS 评分，比二元安全标签提供更精细的遏制本地化信息，能区分早期拒绝与晚期阻断。
- **严格的证据门槛**：违规判定基于可观察执行证据（工具事件、工件哈希、蜜罐 canary），不采信模型自述；N5b 要求精确 canary + 触发阶段归属，标准严苛。
- **完备的控制实验设计**：五个匹配对照组 + 279 案例的严格配对支持，验证了攻击链的因果归因。
- **透明的不合格处理**：对无支持的映射（unsupported）、工作流未完成（N−1）、执行无效（invalid）等类别不做安全解释，避免负面案例被错误当作安全信号。
- **案例构建流程严谨**：程序化扩展 + 模型辅助筛选 + 人工审查三重保障，确保条目可执行、绑定可验证。

## 8. 不足与局限

- **可复现性受限**：论文明确承认部分配置没有统一的时间戳/解码参数记录、部分证据仅具代表性而非穷尽性、实验三的案例级配对记账未发布；T3-A 仅 6 个案例，统计功效不足。
- **每次案例仅执行一次**：未报告多次运行的方差分析，无法估计配置间差异的统计显著性。
- **覆盖面存在缺口**：Kimi Code 和 OpenCode 覆盖不足（61.59%/78.66%），其结果带 * 号标记不可直接与全支持配置比较；OpenCode 在 Tier 2 和 Tier 3 部分家族无支持。
- **API 调用成本与算力未披露**：不利于后续研究者评估复现成本。
- **权限配置激进**：实验采用各框架最宽松的非交互式权限模式（如 skip-permissions、Danger-full-access、Yolo mode），作者声明这不是产品默认设置，但实际部署中具有更高权限的配置（如管理员环境）的适用性仍需谨慎。
