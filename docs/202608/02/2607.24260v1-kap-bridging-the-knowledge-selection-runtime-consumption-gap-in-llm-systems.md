## 摘要
现代LLM系统越来越依赖知识选择过程，这些过程产生高价值的结构化先验信息，如排序证据、图拓扑、多模态对齐和置信度信号。然而，LLM服务从根本上对这些丰富结构视而不见：一旦此类信号被序列化到提示中，后端仅观察到扁平的标记序列，迫使解码期间对完整键值（KV）状态进行稠密且均匀的消费。我们将这种架构错位称为知识选择-运行时消费（KSRC）鸿沟：更丰富的上下文扩大了完整提示的KV占用和解码时的内存流量，即使推理仅依赖上下文的一小部分，也会增加延迟并降低吞吐量。为弥合这一鸿沟，我们提出知识访问规划（KAP），一种范式转变的执行抽象，将结构化知识先验从被动的提示构建提示提升为一等物理执行工件。KAP建立了一种通用的中间表示（IR）——运行时访问计划，它编译结构化知识信号以管理物理KV访问，而不改变逻辑提示语义、模型权重或训练过程。通过该IR，KAP将LLM服务从感知标记的上下文消费转变为计划驱动、知识感知的运行时消费。我们用GraphSpec实例化KAP，这是一种将结构化知识选择连接到LLM服务后端的编译器-执行器实现。我们推导了计划引导执行的加速正增益区域的相位边界模型。在4K-128K长上下文问答工作负载中，GraphSpec保持了与全上下文解码相当的答案质量，同时将物理KV消费与提示长度解耦，在128K时将提案时KV访问减少到源KV状态的5.5%，并从根本改变了长上下文生成的扩展轨迹。

## Abstract
Modern LLM systems increasingly rely on knowledge-selection processes that produce high-value structured priors, such as ranked evidence, graph topology, multimodal alignment, and confidence signals. Yet LLM serving remains fundamentally oblivious to this rich structure: once such signals are serialized into a prompt, the backend observes only a flat token sequence, forcing dense and uniform consumption of the full key-value (KV) state during decoding. We term this architectural mismatch the Knowledge Selection-Runtime Consumption (KSRC) gap: richer contexts enlarge the full-prompt KV footprint and decode-time memory traffic, increasing latency and degrading throughput even when reasoning depends on only a small fraction of the context. To bridge the gap, we propose Knowledge Access Planning (KAP), a paradigm-shifting execution abstraction that elevates structured knowledge priors from passive prompt-construction hints into first-class physical execution artifacts. KAP establishes a universal intermediate representation (IR)-the runtime access plan-which compiles structured knowledge signals to govern physical KV access without altering logical prompt semantics, model weights, or training procedures. Through this IR, KAP shifts LLM serving from token-aware context consumption to plan-driven, knowledge-aware runtime consumption. We instantiate KAP with GraphSpec, a compiler-executor realization connecting structured knowledge selection to an LLM serving backend. We derive a phase-boundary model for the positive-speedup regime of plan-guided execution. Across 4K-128K long-context QA workloads, GraphSpec maintains answer quality comparable to full-context decoding while decoupling physical KV consumption from prompt length, reducing proposal-time KV access to 5.5% of source KV state at 128K, and fundamentally shifting the scaling trajectory of long-context generation.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心现象（KSRC鸿沟）**：现代LLM系统越来越依赖上游知识选择流程（如RAG、GraphRAG、HippoRAG等），这些流程能产生丰富的结构化先验——排序证据、图拓扑、证据片段、置信度信号等。然而，这些高维结构信号一旦被序列化进prompt，LLM服务后端就只能看到一个扁平的token序列，对该序列进行无差别的均匀消费（即解码时逐token访问全部KV缓存）。
- **核心矛盾**：知识选择已经变得"结构感知"，而LLM推理服务仍然是"token感知"。上下文越丰富，KV缓存占用和解码期内存流量越大，延迟上升、吞吐下降——即使模型推理只需要其中一小部分上下文。
- **问题本质**：前端已经用大量算力确定了哪些知识重要，但后端不知道也不使用这个信号，导致前端语义计算和后端内存带宽都在被浪费。
- **论文主张**：需要一种范式转变，把知识选择的结构化先验从"prompt构建提示"升级为"第一等的物理执行工件"，使服务端的物理KV消费受知识规划驱动，而非受token布局驱动。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

**（1）核心思想：KAP（Knowledge Access Planning，知识访问规划）**

- 提出一种通用执行抽象，以**运行时访问计划（Runtime Access Plan）**作为连接知识选择前端与LLM服务后端的**通用中间表示（IR）**。
- 通过该IR，将结构化知识先验编译为后端的物理KV访问策略，不改变逻辑prompt语义、模型权重或训练过程。
- KAP采用**编译器—执行器**分工架构：
  - **KAP编译器**：把高维知识先验（相关性、图结构、置信度等）编译为运行时访问计划。
  - **KAP执行器**：在服务后端解释该计划，执行计划引导的KV访问，并应用验证/回退策略。

**（2）运行时访问计划的形式化表示**

\[
A = (U, M, pos, \rho_{access}, \rho_{verify})
\]

- **U**：选中的知识单元（selected knowledge units）
- **M**：知识单元到运行时对象（token span、KV对象、缓存块、注意力区域）的映射
- **pos**：逻辑位置（保证物理重排不改变模型感知的位置语义）
- **ρ_access**：运行时访问策略
- **ρ_verify**：验证策略（保证选择执行正确性）

计划需满足三个不变量：先验保留、逻辑位置保留、验证感知执行。

**（3）GraphSpec实例化**

- 以Graph-RAG为知识选择前端、vLLM为服务后端，实现KAP的具体参考实现。
- **编译流程四阶段**：证据接地→预算感知语义选择→KV页解析与紧凑视图物化（保留逻辑位置）→发射运行时访问计划（含block table、slot mapping等）。
- **执行机制**：采用"**选定KV自推测 + 全上下文验证**"策略：
  - 提案路径：基座模型在选定KV视图上，以 q_prop=1 逐token生成候选token（仅暴露选定KV页）。
  - 验证路径：以全上下文KV验证候选token，采用Top-3宽容验证策略（候选token若在目标模型全上下文top-3内则接受），一次验证同时推进全上下文状态，无需额外重新同步。

**（4）相位边界（Phase Boundary）成本模型**

- 基本假设：内存受限视角，全上下文解码单步成本为：

\[
Cost_{full} \approx W_{main} + KV
\]

其中 W_main 是权重内存读取成本，KV 是全部历史KV读取成本。

- 定义保留KV比 s 和提案接受率 h 后，计划周期与全上下文基线对比，推导出**正加速区间的理想化条件**：

\[
(h - s)KV > (1 - h)W_{main}
\]

- GraphSpec自推测中 W_prop = W_main，因此基本条件简化为 **h > s**（必须有正的KV侧接受—保留边际）。
- 理想化临界KV规模：

\[
KV_{crit} \approx \frac{(1-h)W_{main}}{h-s}
\]

即KV规模越大（上下文越长），计划越容易进入正加速区间——KAP天然面向长上下文。

### 3. 实验设计：数据集、Benchmark与对比方法

- **数据集**：SPIQA（科学论文图表+文本的多模态QA基准）。为控制上下文长度，作者**不换数据集**，而是对每个查询保留答案和核心证据不变，追加查询特定的硬负样本（hard negatives）来构造不同上下文长度：**4K、8K、16K、32K、64K、128K**六个级别，形成嵌套长度扫描。
- **评测指标**：
  - 服务效率：解码吞吐（TPS）、首token延迟（TTFT）、提案KV可见比（s）、Top-3宽容接受率（h）、h-s。
  - 答案质量：LLM-as-judge 四维加权相似度评分（事实一致性40%、信息完整性30%、逻辑结构20%、表达质量10%），通过率阈值0.5；并进行了100样本的盲审人工验证（人-机一致率95%）。
- **对比方法**：
  - **Full-context baseline**：标准vLLM全解码。
  - **GraphSpec**：KAP实例（完整逻辑prompt + 计划引导KV选择）。
  - **Physical concat**：把GraphSpec选出的同一证据物化为短prompt的对照实验（消除运行时访问计划变量）。
  - **Random concat**：随机选段落拼接的prompt压缩基线。
  - **Local window**：按位置保留固定窗口的prompt压缩基线。
- **四个研究问题**（RQ1-RQ4）：
  - RQ1：GraphSpec是否解耦物理KV消费与序列化上下文增长？
  - RQ2：在保持答案质量的同时，跨上下文长度是否持续高效？
  - RQ3：运行时访问计划是否真正桥接知识选择与运行时消费？
  - RQ4：实测加速趋势是否与相位边界分析一致？

### 6. 论文的主要结论与发现

- **RQ1（解耦效果）**：随上下文从4K增长到128K，GraphSpec提案阶段KV访问比从40.1%降至5.5%；接受率保持在0.95以上；解码吞吐加速从1.08×提升到1.19×——物理KV消费与序列化上下文长度成功解耦。
- **RQ2（质量保持）**：GraphSpec在6档长度上的通过率与全上下文基线相差不超过0.3个百分点（64K档还高出1.9个百分点），平均相似度基本持平——效率提升不以牺牲答案质量为代价。
- **RQ3（机制归因）**：Physical concat虽用相同选择证据（0.95K token短prompt），通过率却降至73.9%（GraphSpec为87.9%）；Random concat和Local window仅49.7%和47.1%——只做证据选择或prompt压缩不足以弥合KSRC鸿沟，运行时访问计划才是关键桥梁。
- **RQ4（理论一致性）**：h-s边际从0.557（4K）增至0.897（128K），实测加速趋势与相位边界预测一致——验证了理论模型的方向性正确性。
- **总体结论**：知识先验必须从"prompt构建提示"升级为"物理执行工件"，KAP提供了一种范式级的解答，使长上下文生成的服务成本随上下文增长呈**亚线性**扩展。

### 7. 优点

- **问题定义清晰且高价值**：精准识别了知识选择前端与LLM服务后端之间的架构错位，是一个此前未被系统化的真实系统瓶颈。
- **方法论抽象度高**：运行时访问计划作为通用IR，与具体模态、模型架构、服务框架解耦，具有跨RAG、GraphRAG、智能体记忆、多模态等场景的通用潜力。
- **编译器—执行器架构合理**：职责分离清晰——编译器负责语义到物理的翻译，执行器负责物理落地，两者可独立演进。
- **理论建模有深度**：相位边界模型将知识先验质量转化为可量化的执行效用，为"知识选择-执行协同设计"提供了形式化分析工具；结论（KV越大越有利、k不决定能否进入正加速区）对工程实践有直接指导意义。
- **实验控制严谨**：嵌套长度扫描、冻结检索结果、物理拼接消融等设计，有效地分离了变量、排除了干扰解释。
- **工程落地性强**：在vLLM上实现了可部署的参考实现，并讨论了CUDA graph、形状稳定、工作空间复用等实际性能优化细节。

### 8. 不足与局限

- **实验场景单一**：只测了SPIQA（论文QA），未覆盖代码生成、对话、多文档摘要等典型长上下文场景。
- **模型泛化不明**：只在Qwen3-VL-32B上验证，未测试不同规模、不同架构的模型。
- **基线对比不够全面**：未与KV缓存压缩类（H2O、SnapKV、Quest、StreamingLLM等）和提示压缩类（LLMLingua等）主流方法直接对比；与其他推测解码方案（如TriForce、RAPID）也无竞争性评测。
- **收益规模有限**：实际吞吐加速仅1.08×-1.19×，虽然趋势正确，但绝对收益不算很大；相位边界显示收益依赖于特定的KV规模条件。
- **评估主观性残余**：LLM-as-judge虽经盲审校准，但单基准、单阈值（0.5）的设定仍可能引入系统性偏差。
- **已验证的实现空间较窄**：论文只探索了"选定KV自推测+全上下文验证"一种执行策略，其他KAP执行器（如tiered-KV、异构执行等）尚未实证。
- **计算成本细节缺失**：未披露查询数量、总实验时长、前端Graph-RAG编译开销、计划编译耗时占整体延时的比例等具体数据。
- **安全性/稳健性**：未讨论计划验证失败率高时的回退策略开销、以及高并发调度场景下紧凑KV工作区是否会成为资源瓶颈。
