## 摘要
全模态大语言模型（OmniLLMs）正迅速扩展多模态推理能力，以覆盖同步音频和视频。然而，由此产生的音频-视频令牌序列较长，导致推理时预填充延迟高且GPU内存占用大。现有的令牌剪枝方法主要针对纯视觉输入设计，既忽略了音频与视频之间的跨模态关联，也未考虑决定内容重要性的用户查询。为弥补这一空白，我们提出了Omni-Prune，一个无需训练、查询感知的音频-视觉令牌剪枝框架，可联合去除两种模态的冗余，同时保留与任务相关的跨模态证据。具体而言，Omni-Prune首先将令牌序列分割为位于音频显著性峰值处的自适应时间窗口，然后在结合编码器注意力与文本查询相关性的统一尺度上对音频和视频令牌进行评分，并将相关联的音频-视觉令牌配对以使其被共同保留。在每个窗口内，最终的K-medoids步骤会选择少量代表性令牌，从而增加仅凭基于评分的选取所遗漏的多样性线索。大量实验表明，Omni-Prune优于既有基线方法，可实现高达3.25倍的预填充加速和1.3倍的内存减少，同时保留全模型超过99%的性能。

## Abstract
Omnimodal large language models (OmniLLMs) are rapidly extending multimodal reasoning to cover synchronized audio and video. However, the resulting audio-video token sequences are long, leading to high prefill latency and GPU memory usage at inference time. Existing token pruning methods, designed mainly for vision-only inputs, miss both the cross-modal links between audio and video and the user query that decides which content matters. To bridge this gap, we present Omni-Prune, a training-free, query-aware audio-visual token pruning framework that jointly removes redundancy from both modalities while keeping task-relevant cross-modal evidence. Specifically, Omni-Prune first splits the token sequence into adaptive time windows placed at audio saliency peaks, then scores audio and video tokens on a single scale that combines encoder attention with text-query relevance, and pairs related audio-video tokens so that they are kept together. Within each window, a final K-medoids step then selects a few representative tokens, adding diverse cues that score-based selection alone would miss. Extensive experiments demonstrate that Omni-Prune outperforms established baseline methods, delivering up to 3.25x prefill speedup and 1.3x memory reduction while retaining over 99% of full-model performance.

- **现有方法的不足**：
  - 面向图像/视频大语言模型的剪枝方法（如 FastV、DyCoke）仅处理视觉输入，无法利用音频与视频之间互补且时间对齐的证据。
  - 面向全模态的剪枝方法（如 OmniZip、OmniSIFT）采用**单向顺序管线**（一模态单向驱动另一模态的压缩），而非对称地双向协同；且完全**忽视用户文本查询**在决定内容重要性中的作用。
- **核心缺口**：尚缺乏一种能同时利用音频、视频、文本三种模态信息来指导令牌剪枝的方法。Omni-Prune 正是针对这一空白提出的**首个训练无关、查询感知的统一音视频令牌剪枝框架**。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体框架

Omni-Prune 是一个 **training-free（无需训练）** 的即插即用剪枝框架，包含三大核心模块：

1. **Audio-Anchor Adaptive Windowing（AAW）**——音频锚定的自适应时间窗口划分
2. **Cross-Modal Relation Map（CMRM）**——跨模态关系图（统一评分 + 跨模态配对）
3. **Diversity-Preserving Clustering**——基于 K-medoids 的多样性保持聚类

### 2.2 模块一：AAW（音频锚定自适应窗口化）

- **动机**：有意义的语义事件在时间上不均匀分布，固定窗口会切断连贯事件，全局处理忽略局部结构。
- **音频显著性计算**：将音频令牌序列均匀分为 F 段（每段对应一帧视频），每段音频能量定义为该段内令牌编码器注意力得分的均值；随后用核大小为 3 的 1D 平均池化平滑，抑制瞬态波动，得到平滑显著性曲线。
- **峰值引导分割**：以平滑曲线的局部峰值（同时不低于左右相邻值）作为候选窗口边界；相邻边界间约束最小间隔 f_min=2，抑制噪声峰值并避免碎片化。
- **优势**：音频峰值（语音起始、音效、音乐转换）常与重要视频时刻共现，天然构成内容连贯的窗口边界；音频序列短，峰值检测仅需 O(F) 复杂度。

### 2.3 模块二：CMRM（跨模态关系图）

**（1）令牌重要性评分（Token Importance Scoring）**

- **编码器注意力得分**：取最后一层编码器自注意力，对所有头取平均、对所有 query 位置求和，得到每个令牌的注意力显著性 s_i。
- **联合归一化**：在窗口内对音频和视频令牌的注意力得分**一起**做 min-max 归一化（而非各模态独立归一化），使两种模态落在同一 [0,1] 尺度上，支持直接的跨模态比较。
- **文本查询相关性**：计算每个多模态令牌嵌入与所有查询文本令牌嵌入的余弦相似度，经仿射映射到 [0,1]：
  r_text^i = ( max_j (x_i^T t_j / (‖x_i‖·‖t_j‖)) + 1 ) / 2
- **复合得分**：φ_i = v_i + r_text^i，融合模态内显著性（encoder attention）与任务意图（query relevance）。

**（2）候选选择**

- 归一化得分超过窗口平均值的令牌，或文本相关性超过 max(平均文本相关性, τ) 的令牌，被标记为 keep 候选；τ=0.55 作为相关性下限阈值。
- 窗口内按 φ 排序取 top-k，其中 B_w^keep = ⌊α·ρ_keep·(|A_w|+|V_w|)⌉，ρ_keep=0.6 为窗口内保留上限，为后续跨模态配对留出预算空间。

**（3）跨模态配对（Cross-Modal Coupling）**

- 关键观察：某些音频令牌和视频令牌代表同一底层事件，应成对保留。在窗口内计算音视频令牌对之间的余弦相似度矩阵 C^w。
- 对未选中的令牌，使用**双向贪心匹配**将每个音频令牌与其最相似的视频令牌配对；相似度超过门控阈值 γ=0.6 的配对被联合保留。
- 剩余预算按 φ 得分优先补充，且偏好少数模态以维持跨模态平衡。

### 2.4 模块三：多样性保持聚类（Diversity-Preserving Clustering）

- **动机**：未被选中的令牌并非全部无用——它们可能携带环境音、背景物体等补充细节；直接丢弃会导致保留集在嵌入空间中过度集中于高分事件所在区域。
- **方法**：在每个窗口内、每种模态内，对未选中令牌独立执行 **K-medoids 聚类**，采用余弦距离 + 最远点遍历贪心初始化，选择 ρ_c=0.1 比例的 medoid 令牌保留。
- **选 K-medoids 而非 K-means** 的原因：medoid 是编码器真实产生的令牌，而 K-means 质心是平均向量，会偏离分布（out-of-distribution），对下游 LLM 有害。
- 复杂度为 O(k·n) 每窗口，开销可忽略。

### 2.5 完整算法流程（文字化描述）

**Stage 1（Algorithm 1）**：计算每帧音频能量 → 平滑 → 检测局部峰值 → 施加最小间隔过滤 → 由边界集合 B 派生窗口集合 W。

**Stage 2（Algorithm 2）**：对每个窗口：联合归一化音视频注意力得分 → 计算文本查询相关性 → 得到复合分 φ → 确定候选集合 Q → 选出 top-k 保留集 K^w → 计算音视频相似度矩阵 C^w → 双向贪心匹配得到配对集 P^w。随后全局按 φ 降序填充预算 B，再按 P 中配对依次补充（成对占 2 个名额），最后剩余名额偏好少数模态填充。最终生成二进制掩码 m，保持原始令牌顺序构造剪枝后序列 X'。

## 6. 主要结论与发现

1. **近乎无损的剪枝**：7B 骨干下，45% 保留率保持 99.2% 精度，35% 保留率仍保持 99.0%，均优于所有基线。
2. **效率提升显著**：7B 模型 35% 保留率下，预填充时间从 899ms 降至 277ms（**3.25× 加速**），峰值显存减少 6.4G（约 **1.3× 缩减**）；3B 模型更达 3.63× 加速。
3. **在部分基准上超过全 token 模型**：VideoMME、OmniVideoBench、FutureOmni 上剪枝后的模型精度超过 full-token 基线——提示剪枝可充当温和的"降噪器"，去除与答案无关的冗余上下文。
4. **模型规模效应**：3B 骨干对剪枝更敏感，方法间差距在激进预算下显著拉大；Omni-Prune 的优势在较小模型上更明显，说明优势源于更优的令牌选择本身而非大模型的冗余容量掩盖缺陷。
5. **消融结论**：Scoring 比 Coupling 贡献更大；聚类的作用随剪枝激进程度和音视频密度增大而增强；AAW 优于任何固定窗口设置；ρ_keep=0.6 为最优平衡点。

- **良好的可解释性**：附录详细给出算法伪代码、符号表、案例可视化，便于复现和理解。

## 8. 不足与局限

- **评测覆盖有限**：仅覆盖视频问答（QA）任务，未涉及开放式描述（captioning）、多轮对话等同样重要的全模态下游任务——这些任务往往依赖人工评测且对剪枝的响应可能不同。
- **超参数固定受限**：τ、γ、ρ_c、f_min 全数据集统一固定，是"开箱即用"的取舍；面对差异显著的音视频密度（如长视频 vs 短视频），自适应/逐数据集调优或可进一步提升。
- **基线无法完全跑全**：FastV 在 VideoMME 上 OOM，其条目被排除在平均之外，造成基线比较存在轻微的不完整。
- **主实验未提对比 OmniSIFT**：相关工作提到的同日/同期方法 OmniSIFT 未出现在实验对比中（可能因发布时间接近）。
- **效率开销的量化不够充分**：虽然声明剪枝开销可忽略，但未给出剪枝本身耗时与端到端加速的分解对比，读者无法准确衡量预填充加速中有多少来自剪枝本身、多少来自减少的注意力计算。
- **单卡、单模型族验证**：仅用 Qwen2.5-Omni 家族（3B/7B）和 A6000 单卡验证，未覆盖其他 OmniLLM 架构（如 Baichuan-Omni、VITA 系列）或分布式/边缘部署场景，泛化性证据有限。

## 9. 总评

Omni-Prune 在方法层面实现了一个值得称道的范式转变：将剪枝从"模态内显著性筛选"升级为"模态间耦合 + 任务意图驱动的统一决策"。其在 7B 模型上以 45% 保留率维持 99.2% 精度并在效率上取得 3.25× 预填充加速，结果令人信服。尽管在评测广度、超参数自适应、量化开销细节上尚有改进空间，但作为首个查询感知的全模态统一令牌剪枝框架，该工作对 OmniLLM 高效推理研究具有明确的推动价值，其"无训练 + 即插即用"的特性也使其具备良好的实际部署前景。
