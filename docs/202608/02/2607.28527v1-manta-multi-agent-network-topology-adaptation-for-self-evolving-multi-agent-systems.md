## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题的求解能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出了MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自进化。在执行前，MANTA根据先前的结构经验初始化一个任务条件化的拓扑。在部署期间，它会监控协作轨迹，并在当前组织变得不足时应用有界的结构更新。这些更新可以修改智能体角色、通信链路、执行顺序、信息可见性和验证路径，同时保持任务接口和智能体预算不变。我们在五个基准上评估了MANTA，涵盖信息寻求、工具使用、规划、工作流执行和数学推理，并与代表性的单智能体和多智能体基线进行比较。MANTA取得了74.0的最高平均分，比最强基线高出5.8个百分点，并在PlanCraft上获得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

- **现有局限**：以往工作大多把通信拓扑视为**固定设计**或**离线优化目标**。自动工作流设计方法（如 AFlow、ADAS、AgentSquare、MASS）虽然在执行前搜索/优化拓扑，但选定结构后通常**不再改变**。很少有系统能在任务执行过程中根据实际协作情况动态调整自己的组织结构。
- **核心问题**：一个多智能体系统能否在解决每个任务的过程中，**同时改进自身的通信拓扑**？这要求系统具备实例条件化规划、从中间协作轨迹进行测试时突变，以及跨运行迁移拓扑经验的能力，且不更新模型权重。
- **整体含义**：MANTA 提出“拓扑级自我改进”，将自我进化的层次从输出、提示、推理链、技能/工具、记忆、角色延伸到**协作架构本身**，填补了该层次上的空白，并验证了执行时自适应组织结构能显著提升复杂任务求解能力。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
- MANTA 将多智能体通信拓扑视为一种**运行时可修改的对象**：执行前根据积累经验规划一个任务条件化初始拓扑；执行中监控协作轨迹；当发现过程性异常时，应用**一次受限的结构性改造**；跨运行通过“长期战术手册”持续学习并传递可复用的拓扑选择经验。
- 全过程**不改变模型权重**，不依赖基准答案或离线搜索，只使用过程信号（可观测的协作缺陷）指导决策。

### 2.2 系统架构与流程
系统有两层嵌套结构：
- **目标多智能体系统**：负责实际执行任务，包括推理、工具调用和消息交换。
- **编排层**：负责选择智能体、通信链路、信息可见性，并监控与修复组织。

主要流程分为几个阶段：

1. **查询条件化规划**：Topology Planner 接收任务文本和经验记忆，分析任务类型、属性、失败风险，输出一个紧凑的 JSON 计划（包括交互模式、智能体数量、可选验证者、嵌套分组）。确定性代码将该计划扩展为完整拓扑，并校验结构约束（角色、分组、循环、预算等）。
2. **轮次执行**：按拓扑递归执行，智能体通过结构化数据包（relay packets）交换摘要、证据、置信度和未解决问题；共享上下文控制器按每个智能体的可见性策略过滤信息；相同工具调用去重，证据账本以追加方式记录所有声明与证据。
3. **轨迹审计与修复**：每轮结束后，Trace Auditor 扫描结构化工件、工具记录、数据包、置信度、未解决问题和证据可见性，输出过程风险标记（不判断答案对错）。如果存在中/高严重度的可修复标记，则 Controller 允许**至多一次有界结构突变**（至多 3 个操作），然后执行最终一轮。
4. **两时域记忆**：
   - **短时战术手册（run 内）**：记录每一轮使用的拓扑、审计发现、修复建议和决策，供 Planner 在修复时参考。
   - **长时战术手册（跨 run）**：存储通用的“拓扑选择技能”，由 Skill Reflector 每 N 次运行基于过程信号批量重写；该学习过程**从未接触基准真值**。

### 2.3 关键设计细节
- **拓扑表示**：支持 root 模式（star、chain、debate、voting、singleton）、嵌套分组、直接连接、上下文策略；含单一智能体和多种固定工作流作为特例。
- **拓扑突变算子**：`add_agent`、`expand_agent_to_group`、`set_group_pattern`、`add_edge`/`remove_edge`、`set_context_policy`；均需过结构化校验，无效提案被拒绝。
- **确定性审计分类**：预定义 11 种过程异常模式（如 tool_error_cascade、branch_collapse、premature_consensus、duplicate_state_mutation、missing_validator 等），LLM Auditor 可追加新的轨迹相关标记。
- **上下文管理**：智能体无状态，所有历史存在共享的追加式存储（数据包、证据账本、候选列表）；拓扑突变只需重新指向上下文控制器，无需迁移或丢失状态。
- **确定性守卫**：重复调用检测、停滞搜索检查、失败熔断、强制最终答案等，保证不产出空结果。

## 6. 主要结论与发现

- **主结果**：MANTA 在 5 个基准的平均分为 **74.0**，超过最强基线 5.8 个百分点；在 PlanCraft 上取得最佳结果（76.7），且在每个基准上都优于单一智能体。
- **消融**：删除任务条件化初始规划导致最大性能下降（71.7→57.5）；删除拓扑突变使平均分降至 60.8；删除/冻结长期手册也带来较小但一致的下降。初始规划与执行时修复贡献最大，跨运行记忆提供额外收益。
- **突变预算**：从 0 到 3，各基准成功率递增；第一次突变带来的增益最大，说明“一次有界修复”能覆盖大部分可修复问题。
- **迁移性**：MANTA 的长期手册在同域和跨域迁移中均产生正收益（平均 +3.3 分），而对比的自适应基线（ADAS、AgentSquare、MASS）跨域迁移多为负或严重负值，说明 MANTA 学到的是可泛化的结构知识而非基准特定工作流。
- **Token 效率**：MANTA 是所评估多智能体系统中 token 总消耗最低的，元层开销仅约占推理预算的 12%，表明有针对性规划/修复并不需要大量额外计算。
- **审计有效性**：无修复标记的运行中答案正确率为 83.2%，有标记的运行正确率为 62.5%，两者相差 20.7 个百分点；审计能识别 117 个错误运行中的 75 个，但存在较大代理偏差（如 BrowseComp 检索异常可恢复导致高假阳性）。
- **修复性质**：151 次修复中，多数修复改变的是执行结构（模式切换、分支扩展、串行化），而非单纯增加智能体；新增智能体仅占算子使用量的 9.3%。拓扑进化既可以是添加边、改变顺序，也可以是插入校验角色。

## 7. 优点

- **提出新问题/范式**：将“拓扑级自我改进”从离线设计提升到执行时在线自适应，具有一定原创性。
- **方法设计精巧**：将 LLM 元智能体（规划/审计/反思）与确定性代码（拓扑校验、执行控制、守卫）结合，兼顾灵活性与可靠性。
- **全程过程信号驱动**：审计不依赖基准答案，长期记忆仅基于过程标签，保证了自我进化过程中的信息隔离，避免作弊。
- **有界、保守的修复策略**：每次至多 1 次突变、至多 3 个操作，保留任务接口和智能体预算，避免无节制规模膨胀；案例显示修复可以只改变一条边或插入一个验证者。
- **跨运行记忆迁移**：通过长期战术手册实现了同域和跨域的正向迁移，优于对比的离线优化方法。
- **Token 效率高**：在提升性能的同时使用更少的 token，说明自适应拓扑并不必然带来高开销。
- **分析详尽**：对审计分类、算子使用、修复前后状态、迁移场景均给出统计证据，并包含具体案例（过度负载分支、缺失验证、过早共识、重复动作等）。

## 8. 不足与局限

- **评测规模相对较小**：每基准仅 30 题、3 次运行，很多对比差异的置信区间较宽；缺少更大规模（如数百题）或多次重复的验证。
- **单一 backbone**：只在 Gemma 4 31B 上实验，未验证不同规模或不同系列模型上的普适性，无法排除模型特定性。
- **审计代理标签不可靠**：过程异常标记与答案正确性只是代理关联，并非人工标注的真实过程缺陷；一些模式（如 message_compaction_loss、tool_error_cascade）与成功率无正/负相关，说明审计分类存在噪声。
- **修复策略的限制**：每运行仅允许 1 次拓扑突变，且突变预算上限为 3 个操作，可能无法覆盖需要多轮重组或更复杂调整的任务；实验也显示第二次、第三次突变增益递减，但未探讨更大预算。
- **长期记忆可能累积错误**：长期手册基于过程信号（如“清洁运行”和共识）进行重写，但干净过程与正确结果之间仍有差距（85.8% 正确率），可能把有偏差的经验固化。
- **跨域迁移实验样本有限**：仅涉及 PlanCraft 与 WorkBench 两个相邻领域，未覆盖差异更大的任务类型（如检索→数学），迁移能力的一般性证据不足。
- **部署成本与适用性**：虽然 token 效率高，但需要额外的元层 LLM 调用、审计与校验逻辑；对于简单任务可能仍然显得过重，且文中未给出实际延迟/吞吐量数据。
- **公平性细节可能存疑**：虽然论文声称所有多智能体方法使用相同最大 agent 数和可比推理预算，但静态基线无法像 MANTA 那样动态调整，这种对比在本质上对自适应方法有利；且优化型方法（AFlow、MASS 等）的离线搜索成本是否完全对齐也未详细展开。
