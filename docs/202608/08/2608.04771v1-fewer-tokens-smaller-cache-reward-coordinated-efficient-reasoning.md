## 摘要
大型推理模型（LRMs）通过长思维链（CoT）推理在复杂任务上表现出色，但其冗长的中间步骤会导致严重的过度思考，从而推高推理成本。KV缓存压缩是一种常见解决方案，然而现有的面向推理的方法在轨迹上应用统一策略，并且仅根据从缓存中移除的内容来判断压缩效果。两个观察指向相反方向。首先，推理状态对上下文丢失的容忍度沿轨迹变化，过程奖励能反映这一点：在高奖励步骤删除令牌比随机删除相同预算更能保持准确性。其次，压缩在生成侧并非免费，因为更小的缓存会导致模型生成更多令牌，部分抵消节省。这两点共同表明，应在单一过程奖励下协调两侧。我们提出ReCo（奖励协调压缩），一种逐步框架，其中轻量级过程奖励估计器对每个已完成步骤打分，并驱动三个组件：（1）奖励自适应KV缓存压缩，在高奖励步骤更大幅度缩减保留缓存，在低奖励步骤缩减较少；（2）对反思令牌的奖励分带惩罚，以抑制冗余生成；（3）基于置信度的提前停止，在推理可靠时触发。在三个推理模型和六个基准测试中，与完整CoT相比，ReCo将生成令牌减少37%-65%，端到端延迟降低2.08倍-2.35倍，同时基本保持准确性。

## Abstract
Large Reasoning Models (LRMs) excel on complex tasks through long chain-of-thought (CoT) reasoning, but their lengthy intermediate steps cause severe overthinking that inflates inference cost. KV-cache compression is a common solution, yet existing reasoning-oriented methods apply a uniform policy across the trajectory and judge compression only by what it removes from the cache. Two observations point the other way. First, a reasoning state's tolerance to context loss varies along the trajectory, and process reward tracks it: deleting tokens at high-reward steps preserves accuracy far better than deleting the same budget at random. Second, compression is not free on the generation side, since a smaller cache leads the model to generate more tokens, partly canceling the saving. Together these motivate coordinating both sides under a single process reward. We propose ReCo (Reward-Coordinated Compression), a step-wise framework in which a lightweight process-reward estimator scores each completed step and drives three components: (1) reward-adaptive KV-cache compression that shrinks the retained cache harder at high-reward steps and less at low-reward ones, (2) a reward-banded penalty on reflection tokens that curbs redundant generation, and (3) confidence-based early stopping that triggers when the reasoning is reliable. Across three reasoning models and six benchmarks, ReCo reduces generated tokens by 37%-65% and end-to-end latency by 2.08x-2.35x over Full CoT, all while largely preserving accuracy.

## 1. 核心问题与整体含义

- **研究背景**：大型推理模型（LRMs）如 OpenAI-o1、DeepSeek-R1、Gemini 等，通过长链思维（Long Chain-of-Thought）在复杂推理任务上取得显著成效，但也由此带来了严重的“过度思考”（overthinking）问题——模型即便面对简单输入也会生成极长的推理链，导致 token 开销、推理延迟和计算成本大幅上升。
- **已有方法与不足**：KV 缓存压缩是缓解推理成本的主流思路，但现有面向推理的 KV 压缩方法（如 R-KV、RPC、SnapKV 等）存在两个关键缺陷：
  - **统一策略**：在整个推理轨迹上应用相同的压缩率，忽略了不同推理步骤对上下文丢失的容忍度差异；
  - **只从缓存侧度量收益**：仅关注压缩删除了什么，没有考虑压缩对后续生成长度的影响。
- **两项关键观察**：
  - 过程奖励（process reward）可以可靠地追踪推理状态的压缩容忍度——高奖励步骤（推理路径可靠、已上正轨）更能承受激进裁剪，低奖励步骤（仍在探索、状态脆弱）则经不起上下文损失；
  - KV 缓存压缩会诱发模型生成更多 token——在 MATH-500 上，R-KV 在 25% 压缩率下使平均生成长度增加 38.8%（Qwen-7B）至 79.0%（Llama-8B），且高达 79.8% 的问题在压缩后输出更长。
- **核心论点**：KV 缓存压缩不能独立于生成控制存在，二者应在统一的奖励信号下协同完成，才能同时降低 token 数和延迟且保持准确率。

## 2. 方法论：ReCo（Reward-Coordinated Compression）

### 核心思想

ReCo 以“推理步骤”为控制粒度，在每步完成后用轻量级过程奖励估计器打分，一个奖励信号同时驱动三个组件——压缩、生成控制和停止决策，使三者保持一致，在推理产出高的地方投入计算，在模型已趋稳定时收敛开销。

### 关键技术细节

**（1）推理步骤与奖励信号**

- 推理轨迹 C 按换行符拆分为步骤序列 C = {c₁, …, c_T}，每步对应语义连贯的推理单元；
- 使用 Pilot——一个从 Skywork-o1-Open-PRM-7B 蒸馏出的仅 30M 参数的过程奖励估计器，为每步实时打分 vᵢ ∈ [0,1]，代表当前轨迹最终得到正确答案的可能性。

**（2）奖励自适应 KV 压缩**

- 每当缓存增长超过 S 个 token 即触发压缩；
- 保留比率由最新步骤的奖励决定：

> λᵢ = λ（基础比率）− δ·(vᵢ − v̄) / (v_max − v_min)

即奖励高于轨迹均值时压缩更激进，低于均值时保留更多缓存。其中 λ 为基础保留率，δ 限制调整幅度，确保 λᵢ ∈ [λ−δ, λ+δ]；
- 在给定的保留预算内，用注意力分数选出最关键的 token：以最近 w 个 token 为查询窗口，计算各历史 token 所获得的注意力权重，保留得分最高者，最近 w 个 token 始终保留。

**（3）奖励分带的反思令牌惩罚**

- 构建反思 token 集合（如 “Wait”、“Hmm”、“Alternatively”），在解码时直接抑制其生成；
- 惩罚强度由奖励分带决定（阈值 τℓ < τ_h）：

> 低奖励段：不惩罚（模型可自由反思探索）；中奖励段：半惩罚（β/2）；高奖励段：全额惩罚（β）

惩罚直接在 logit 层面减去 βᵢ，不增加额外前向传播。

**（4）置信度早停**

- 当奖励连续两步维持在高带（vᵢ ≥ τ_h），插入结束提示（“Okay, I think I have finished thinking.”）触发候选答案生成；
- 计算候选答案的困惑度 PPL(a)，若 PPL(a) ≤ τ_p 则停止推理并提交答案；否则丢弃探测结果，继续推理；
- 奖励与困惑度互补——奖励保证推理路径可靠，困惑度确保答案确信度，二者联合避免“自信但错误”的提前终止。

## 6. 主要结论与发现

- **token 数大幅下降**：相比 Full CoT，ReCo 在 Llama-8B、Qwen-7B、Qwen3-8B 上分别减少平均生成 token 的 37%、65%、46%；
- **延迟显著降低**：端到端加速分别达 2.08×、2.35×、2.18×；
- **准确率保持良好**：三个模型上的平均准确率分别为 60.2%（Full CoT 62.8%）、60.0%（61.9%）、69.6%（72.3%），是所有压缩方法中准确率损失最小的；在 AIME25 最难基准上，ReCo 保留 33.3%，而所有 KV 压缩基线均崩至 ≤20%；
- **长度膨胀确凿且普遍**：缓存压缩会让大多数问题生成更长输出（MATH-500 上 15%–40% 压缩区间内超半数问题变长），因此压缩必须与生成控制耦合；
- **三者互补而非冗余**：去掉任何单个组件都会在准确率或 token 数上显著变差；
- **奖励自适应是关键**：δ=0（即统一策略）时准确率明显下降，验证了“奖励指导的按步保留优于统一策略”的核心假设；
- **内存收益显著**：ReCo 在 AIME25 上峰值显存 17.92GB（LLaMA-8B），较 Full CoT 降 37.7%，低于 R-KV（20.70GB）和 SAT（26.90GB）。

## 7. 优点

- **统一信号，协同设计**：用一个过程奖励串联压缩、生成和终止三个环节，逻辑一致、互不冲突，避免了各组件独立调优的失配问题；
- **动机清晰、验证扎实**：先通过两个精心设计的控制实验（高奖励步删除 vs 随机删除；压缩后长度膨胀分析）锚定问题，再提出方法，逻辑链条完整；
- **轻量高效**：Pilot 仅 30M 参数，额外开销约 4%，不增加训练成本（推理模型本身零训练、零微调）；
- **免提示工程、免任务调优**：使用统一超参数（λ=0.25、δ=0.10、τ_p=1.10）跨所有模型和数据集，无需逐任务调整；
- **与现有方法正交兼容**：可叠加在既有 KV 压缩 / 生成控制方法之上，且有明确的注意力与奖励分工——“奖励决定删多少，注意力决定删哪些”；
- **全面的实验验证**：不只报告单一基准，覆盖了主流推理模型的三个不同规模/家族的评测，并给出了内存、延迟、token、准确率的完整画像。

## 8. 不足与局限

- **实验覆盖有限**：
  - 仅评估了 8B 量级的三个模型，未扩展到更大规模（如 70B）或更多模型家族（如 Mamba、混合架构），“奖励→压缩容忍度”的关系是否在更大模型上仍成立尚待验证；
  - AIME24/AIME25 样本量很小（各约 30 题），结果的统计置信度有限；
  - Qwen3-8B 上 AMC 和 AIME25 两个数据集结果缺失；
- **奖励模型迁移性**：Pilot 从 Skywork PRM 蒸馏，其泛化能力到未见过领域（如代码、agent 任务）未知；奖励模型本身的偏差会被 ReCo 放大；
- **潜在算法风险**：
  - 高奖励步骤的“压缩容忍度”可能因奖励分布偏移而不稳定——若某条轨迹整体得分都高，λᵢ 的归一化区间会被压缩失效；
  - 反思 token 的硬惩罚可能对需要真正反思的难题造成准确率损失（实验中确有此信号）；阈值的二分带处理可能存在边界效应；
  - 早停依赖 PPL 阈值，流畅但不正确的答案可能触发误停，论文虽有部分讨论但缺少更细粒度的错误分析；
- **对比基线措辞模糊**：SAT/Dynasor“调到可比加速水平”未给出具体调参过程；R-KV 等基线的压缩率是否与 ReCo 的逐步骤有效压缩率严格可比，不够透明；
- **部署实际性**：Pilot 打分在解耦部署上引入了额外依赖和流水线延迟；实验中总开销约 4%，但实际生产环境中多模型加载、通信开销可能更高；
- **通用性待验证**：ReCo 的方法建立在“过程奖励能反映状态质量”这一假设上，对于思维链质量标注困难的任务（如创造性写作、开放性问答），此信号是否有同样效力未知。
