## 摘要
现有的文本到SQL系统越来越依赖于多轮交互、执行反馈和强化学习。然而，大多数现有方法仅将执行正确性作为轨迹级别的奖励，这在识别导致成功或失败的SQL决策方面提供的指导有限。我们提出了SERL-SQL，一种用于多轮文本到SQL智能体的选择性执行基础强化学习框架。SERL-SQL采样策略内SQL交互轨迹，并使用仅用于训练的教师模型通过执行反馈对学生动作重新评分。由此产生的师生似然差距被转换为有界、掩蔽的权重，这些权重仅对SQL和工具动作标记上的GRPO优势进行重新加权。这样，任务奖励保留优化方向，而执行事后信息提供局部信用分配。在BIRD、Spider和跨域基准上的实验表明，SERL-SQL达到了具有竞争力的性能，在BIRD-Dev上达到76.56%的执行准确率，在Spider-Test上达到89.92%。此外，我们基于奖励的选择策略紧密接近oracle Best-of-N上限，并持续优于基于一致性的选择，表明SERL-SQL产生了可由轻量级执行基础奖励可靠识别的高质量候选。我们的代码将在https://github.com/Ffunkytao/SERL-SQL发布。

## Abstract
Recent Text-to-SQL systems increasingly rely on multi-turn interaction, execution feedback, and reinforcement learning. However, most existing methods use execution correctness only as a trajectory-level reward, which provides limited guidance for identifying the SQL decisions responsible for success or failure. We propose SERL-SQL, a selective execution-grounded reinforcement learning framework for multi-turn Text-to-SQL agents. SERL-SQL samples on-policy SQL interaction trajectories and uses a training-only teacher to re-score student actions with execution feedback. The resulting teacher--student likelihood gap is converted into bounded, masked weights that reweight GRPO advantages only on SQL and tool-action tokens. In this way, task rewards preserve the optimization direction, while execution hindsight provides localized credit assignment. Experiments on BIRD, Spider, and cross-domain benchmarks show that SERL-SQL achieves competitive performance, reaching 76.56% execution accuracy on BIRD-Dev and 89.92% on Spider-Test. Moreover, our reward-based selection strategy closely approaches the oracle Best-of-N upper bound and consistently outperforms consistency-based selection, showing that SERL-SQL produces high-quality candidates that can be reliably identified by lightweight execution-grounded rewards. Our code will be released at https://github.com/Ffunkytao/SERL-SQL.

### 1. 核心问题与研究动机
- **背景**：Text-to-SQL 任务逐渐从单次生成转向多轮交互式 agent 范式（如 schema grounding、SQL 生成、执行验证、迭代修正等），执行反馈与强化学习被广泛用于提升生成 SQL 的鲁棒性。
- **关键痛点**：现有方法（如 SQL-R1、Arctic-Text2SQL-R1）虽然引入执行反馈和 RL，但**只将执行正确性作为轨迹级（trajectory-level）奖励**，所有 token 获得相同的优势值，无法定位导致成功或失败的具体 SQL 决策（如某条 JOIN、WHERE 条件、工具调用）。
- **核心洞察**：执行反馈（运行时错误、空结果、错误结果等）不仅是结果奖励，更应作为**训练时的特权事后信息（hindsight）**，用于对可执行动作 token 进行细粒度的信用分配。
- **研究目标**：在不改变部署策略输入的情况下，利用执行事后信息提供局部、有界、与奖励方向一致的 token 级信用信号，提升多轮 Text-to-SQL agent 的训练效率和最终准确率。

### 2. 方法论：SERL-SQL

**整体架构（四阶段流水线）**：
1. **Schema Grounding（模式接地）**：离线构建列感知向量索引（基于 embedding 模型编码示例值），在线检索问题相关的数据库值；结合基于推理的模式链接（语义结构、投影列、过滤条件、连接键）与基于值的链接，产出压缩的、值感知的 schema 子集 S′。
2. **Multi-turn SQL Agent Rollout（多轮 SQL 智能体轨迹采样）**：策略 πθ 按照"思考 → 动作 → 观察"循环交互；中间 SQL 动作与数据库执行交互，得到结果表、运行时错误、解析错误、空结果等观察；最终提取 SQL 并通过分层验证器得到稀疏轨迹奖励 Rn ∈ {−1, 0, +1}。
3. **Selective Execution-Hindsight Teacher（选择性执行事后教师）**：训练专用教师策略 πT（与学生同步、停止梯度），在观察到执行反馈 c_ex 的条件下对学生采样的同一 token 重新打分，得到师生间对数似然差：
   - **Δ**t,i = log πT(yt,i | ht, yt,<i, c_ex) − log πθ(yt,i | ht, yt,<i)；
   - 定义动作掩码 mt,i，只对 SQL 提交/修正等可执行动作 token 置 1，推理/格式 token 置 0。
4. **Hindsight-Guided Advantage Reweighting（事后引导的优势重加权）**：
   - 将似然差转换为有界、符号感知的权重：wt,i = clip(exp(sgn(An) · sg[Δt,i]), wmin, wmax)；

1. **性能显著**：SERL-SQL-32B 在 BIRD-Dev 达 76.56%，SERL-SQL-14B 在 Spider-Test 达 89.92%（最优），Spider-DK 达 81.68%（14B），在跨域基准上超过多个 32B 强基线。

4. **事后信息需局部且因果对齐**：立即观察最优，完整观察反而带来噪声；错误消息比仅错误类型更有效。
5. **轨迹质量提升**：执行事后信息提高恢复（recovered）轨迹比例，减少格式错误，使多轮交互更稳定。
6. **主要剩余错误**：JOIN 构建（29.1%）和语义理解（24.6%）是主要瓶颈，需要增强细粒度值接地与条件对齐。

### 7. 优点与亮点
- **细粒度信用分配设计精妙**：将轨迹级奖励的方向信息与执行事后信息的位置信息分离，理论动机清晰，公式设计严谨（符号感知、有界裁剪、动作掩码、衰减系数）。
- **训练-部署解耦**：教师只在训练时使用，推理时完全移除，不引入额外推理开销；蒸馏信号仅为重加权权重而非全套模仿，避免信息泄漏和教师偏差。
- **消融全面**：从组件、事后信息来源、选择策略、轨迹质量、错误类型多维度验证设计选择的合理性。
