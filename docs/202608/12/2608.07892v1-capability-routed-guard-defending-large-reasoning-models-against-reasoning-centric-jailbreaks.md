## 摘要
大型推理模型（LRMs）暴露出一种新的安全失效模式：对抗性提示可以操纵推理上下文、任务分解或能力解释，从而使有害目标被当作合法的推理步骤处理。现有的安全措施，包括安全提醒、外部分类器和自检封装器，往往很脆弱，因为它们要么直接检查对抗性提示，要么要求目标模型在被攻击利用的同一表面上执行额外的安全推理。我们引入了能力路由守卫（CRG），这是一种面向闭源LRMs的模型无关的推理时防护栏，在这种场景下防御者无法检查隐藏的推理轨迹或修改模型权重。CRG将提示防御重新定义为能力路由问题：一个侧信道控制器首先构建用户授权任务、活动上下文、安全证据和能力转移风险的可信表示，将可执行意图与不可信的推理上下文分离。该表示支持特定路由的执行，使CRG能够阻止高风险请求、约束模糊请求，并通过可信的活动上下文转发低风险请求。最后，CRG应用TraceCheck来验证与授权任务的一致性，并调用受限的后备机制以保留低风险良性提示的效用。大量实验表明，CRG有效地缓解了各种以推理为中心的越狱攻击，同时保持了良性效用并避免了常见的过度拒绝问题。进一步分析表明，其组件提供了互补的益处，凸显了协调防御机制在保护大型推理模型安全方面的重要性。

## Abstract
Large reasoning models (LRMs) expose a new safety failure mode: adversarial prompts can manipulate reasoning context, task decomposition, or capability interpretation so that harmful objectives are processed as legitimate reasoning steps. Existing safeguards, including safety reminders, external classifiers, and self-checking wrappers, are often brittle because they either inspect the adversarial prompt directly or ask the target model to perform additional safety reasoning on the same surface that attacks exploit. We introduce Capability-Routed Guard (CRG), a model-agnostic inference-time guardrail for closed-source LRMs, where defenders cannot inspect hidden reasoning traces or modify model weights. CRG reframes prompt defense as a capability-routing problem: a side-channel controller first constructs a trusted representation of the user's authorized task, active context, safety evidence, and capability-transfer risk, separating executable intent from untrusted reasoning context. This representation supports route-specific execution, allowing CRG to block high-risk requests, constrain ambiguous ones, and forward low-risk requests through trusted active context. Finally, CRG applies TraceCheck to verify consistency with the authorized task and invokes a restricted fallback to preserve utility for low-risk benign prompts. Extensive experiments demonstrate that CRG effectively mitigates diverse reasoning-centric jailbreaks while preserving benign utility and avoiding common over-refusal issues. Further analysis shows that its components contribute complementary benefits, highlighting the importance of coordinated defense mechanisms for securing large reasoning models.

## 一、核心问题与整体含义（研究动机与背景）

- **新安全失效模式**：大型推理模型（LRMs）因其强大的任务分解、长程推理与多步规划能力，暴露出一种传统对话模型不具备的安全漏洞——**推理中心越狱（Reasoning-Centric Jailbreaks）**。攻击者不再简单要求模型忽略安全策略，而是通过操纵推理上下文、任务分解、权威边界与能力解释，使有害目标被目标模型当作**合法的推理步骤**处理并最终输出。
- **现有防御的局限**：安全提醒（Safety Reminders）、外部分类器与自检封装器等现有手段普遍脆弱，原因在于它们要么**直接检测对抗性提示**，要么**在被攻击利用的同一推理表面上要求模型执行额外的安全推理**——两者都无法切断攻击对推理过程本身的操纵。
- **闭源部署的特殊挑战**：在闭源 LRM 场景下，防御者无法查看隐藏推理轨迹、微调模型权重或修改 provider 侧审核策略，因此防御必须是**推理时（inference-time）**的、并在**有限可观测性**下运行，同时需要在安全性与可用性（utility）之间取得平衡。
- **Capability-Routed Guard（CRG）核心主张**：将提示防御重新定义为"能力路由"问题——通过构建可信的侧信道表示来分离"可执行意图"与"不可信推理上下文"，并据此控制目标模型的执行路径、推理资源与输出验证，实现**端到端执行治理**而非静态过滤。

## 二、方法论：核心思想与关键技术细节

### 1. 核心思想
CRG 的核心是从"判断提示是否安全"转向**"治理目标模型的全执行路径"**。它不是单一分类器，而是由多个协同层组成的执行治理框架。

### 2. 技术流程（侧信道表示 → 路由决策 → 执行控制 → 事后验证 → 后备恢复）

1. **侧信道表示构建（Side-Channel Representation）**
   - 第一阶段：控制器（controller）将原始提示分解为：授权任务（authorized task）、安全证据（safety evidence）、活动上下文（active context）、良性推理价值（benign reasoning value）、能力转移风险（capability-transfer risk）、策略敏感性（policy sensitivity）、初步推理模式（preliminary reasoning mode）及门控理由（gate rationale）。
   - 第二阶段：模式/风险判断器（mode/risk judge）将上述产物转换为**可操作性（actionability）**、**风险分数 r ∈ [0,5]** 和**最终推理模式**。

2. **能力路由执行（Capability-Routed Execution）**
   - 根据风险分数 r 与阈值 Tb（硬阻断）和 Ts（软路由）决定基础路径：
     - **block**：r ≥ Tb，直接拒绝，不调用目标模型；
     - **soft**：Ts ≤ r < Tb，通过受限推理路径执行；
     - **pass**：r < Ts，以完整推理能力执行。
   - 路由并非单纯二分类：若高风险请求被判定为无害常识而非可操作能力转移，则降级为 soft；若检测到异常的目标导向推理需求（如混淆查询包装），则可将默认 pass 升级为 soft。
   - **活动上下文重写**：无论 pass 或 soft，CRG 都会剥离对抗性推理框架，只将干净、任务相关的"活动上下文"发送给目标模型。
   - **推理预算调控**：soft 路径在 API 层面限制推理能力（如将 Gemini 的 `budget_tokens` 上限设为 1024，或将 OpenAI 的 `reasoning_effort` 设为 low），从而压缩攻击者所需的扩展推理空间。

3. **事后验证（TraceCheck）**
   - 对非硬阻断的响应，CRG 用 TraceCheck 审计目标的**公共推理轨迹和最终答案**，与预先提取的"授权任务"对比，验证意图一致性、计划安全性与一致性。
   - 该审计是**风险感知**的：轻微的轨迹异常只有在伴随较高策略风险时才触发硬阻断，避免对复杂良性推理的误伤。

4. **受限后备机制（Low-Risk Fallback）**
   - 当低风险查询因目标模型自身或 provider 的敏感词过滤而被误拒时，若侧信道控制器已判定用户意图为无害常识且无能力转移风险，则由后备模型以**受限、简洁模板**直接回答干净任务，从而提升良性查询的可用性。

### 3. 与静态过滤器的本质区别
- 静态分类器将输入提示直接映射为"阻断/放行"二分类，存在刚性的安全-效用零和权衡。
- CRG 通过**解耦架构**（表示 → 路由 → 上下文控制 → 推理预算 → 事后审计 → 后备恢复）让各层分别对应不同的漏洞或过拒向量，从而同时实现稳健防御与高良性效用。

## 六、主要结论与发现

1. **推理中心越狱的威胁是真实且普遍的**：在未防护的 LRM 上，CoT-Hijacking 和 SEAL 的 ASR 可达 100%，其余攻击也在 28%–98% 之间。
2. **CRG 显著降级攻击成功率**：在所有攻击家族、所有目标模型上，ASR 均降至 15% 以下。例如 HarmBench + Gemini 上 CoT-Hijacking ASR 从 100% 降至 12%，FicDetail 从 97% 降至 0%；HarmBench + o4-mini 上 CoT-Hijacking 从 93% 降至 4%。
3. **现有基线防御脆弱且不一致**：Goal Priority 能抑制 Mousetrap（1% ASR）却在 CoT-Hijacking 上失效（85%）；SecurityLingua 与 IntentionReasoner 在 SEAL 上严重失守（80%/94%）。这表明静态分类范式无法应对推理层面的操纵。
4. **CRG 在保持效用上具有竞争力**：FPR 在 XSTest 和 MT-Bench 上与无防护基线相当（如 XSTest/Gemini 12.0% vs 11.4%），且平均答案质量略有提升——干净上下文帮助目标模型更聚焦于良性请求。
5. **组件互补性**：移除 TraceCheck 使 ASR 从 12% 翻倍至 26%；用扁平过滤替代结构化表示使 FPR 从 12.0% 升至 28.4%；禁用后备机制使 FPR 几乎翻倍。这表明安全与效用由不同组件分别承载，协同配合是关键。
6. **适应白盒攻击仍稳健**：即使攻击者知晓 CRG 提示和路由策略，TraceCheck 能在事后拦截前端门控的漏网攻击，保持最终 ASR 不变。
7. **架构无关性**：CRG 在闭源（Gemini/o4-mini）和开源（DeepSeek-R1/Qwen3-Max）推理模型上均有效，证明其方法不依赖特定目标架构。

## 七、优点

- **范式创新**：将防御从"输入分类"提升为"执行治理"，提出了能力路由、推理预算调控、事后轨迹审计与后备恢复的完整控制框架，解决了静态过滤无法覆盖推理操纵的痛点。
- **面向真实约束**：专门针对闭源 LRM 的 API 级部署条件设计，仅需推理时操作，无需模型内部访问。
- **安全性-效用权衡的架构化处理**：通过分层设计让不同组件分别负责安全性和效用，避免传统零和权衡。
- **模型无关**：在闭源与开源、不同系列的目标 LRM 上均验证有效。
- **实验设计全面**：包含多目标模型、多数据集、多攻击家族、消融、自适应攻击、提取器敏感性和延迟分析，论证充分。
