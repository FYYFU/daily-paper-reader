## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题的解决能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出了MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自演化。在执行前，MANTA根据先前的结构经验初始化一个任务条件化的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在涵盖信息寻求、工具使用、规划、工作流执行和数学推理的五个基准上，将MANTA与代表性的单智能体和多智能体基线进行了评估。MANTA取得了74.0的最高平均分，比最强基线高出5.8个百分点，并在PlanCraft上获得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作本身的结构。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

## 2. 论文提出的方法论

- **方法名称**：MANTA（Multi-Agent Network Topology Adaptation，多智能体网络拓扑自适应）。
- **核心思想**：结合三层能力：
  1. 基于累积经验进行**任务条件化的初始拓扑规划**；
  2. 执行中**审计协作轨迹**，识别过程性缺陷；
  3. 在必要时执行**有界的拓扑变异（mutation）**，并跨运行迁移拓扑经验。
- **系统组成**：
  - 三个LLM组件：**Topology Planner**（拓扑规划器）、**Trace Auditor**（轨迹审计器）、**Skill Reflector**（技能反思器）；
  - 若干确定性代码模块：拓扑校验、智能体运行、消息路由、修复控制、停止判定。
- **拓扑表示**：
  - 每个智能体具有**结构角色**（coordinator、worker、verifier、debater、voter等）和**阶段角色**（worker或critic）；
  - 智能体可归入支持嵌套的模式组（star、chain、debate、voting等）；
  - 通过**上下文策略**控制消息可见性、传播范围、摘要级别；代码在读取信息时强制执行这些策略；
  - 执行前校验组成员关系、环状依赖、角色合法性、智能体预算，拒绝非法提议。
- **编排循环（Orchestration Loop）**：
  1. **查询条件化规划**：Planner接收任务和经验记忆，输出紧凑计划（模式、智能体数量、可选验证器/嵌套组）；确定性代码将其展开为完整拓扑并验证。
  2. **回合执行**：按组结构递归执行；智能体通过结构化“中继包”交流（含答案、证据、置信度、未解决问题）；共享上下文控制器执行可见性策略；相同工具调用去重；使用append-only证据账本。
  3. **轨迹审计与修复**：每回合后Auditor扫描结构化工件、工具记录等，报告过程性风险（非答案正确性）；若存在中/高严重度可修复标志，控制器允许一次有界修复并执行最终回合。每条修复最多包含3个操作（支持add_agent、expand_agent_to_group、set_group_pattern、add/remove_edge、set_context_policy等）。
- **双时域记忆**：
  - **短期剧本**（short-term playbook）：单次运行内记录每轮拓扑、审计标志、修复建议和决策；
  - **长期剧本**（long-term playbook）：跨运行累积经验，由Skill Reflector每N次运行后重写；更新仅使用过程信号，绝不接触基准答案或ground-truth。
- **关键设计细节**：
  - 修复后的下一轮会注入Auditor的一句话建议（作为不可信诊断）；
  - 每轮最佳输出保留为时间候选，最终答案在候选间投票，防止修复使答案变差后覆盖更优的旧候选；
  - 智能体设计为无状态（stateless），所有状态存于共享的append-only存储（包存储、证据账本、候选列表），拓扑变异只需重新指向新的上下文控制器规格，无需迁移或丢失状态。

## 6. 论文的主要结论与发现

- MANTA在五个benchmark上取得**最高平均得分74.0**，比最强基线（ADAS的68.2）高出**5.8个百分点**，并在PlanCraft上取得最佳成绩（76.7）。

- **变异预算**：预算从0增至3时，四类任务成功率均提升；第一次变异带来最大增益，后续变异边际递减。
- **长期剧本可迁移性**：在mutation budget=0时，MANTA在域内迁移（PlanCraft→PlanCraft、WorkBench→WorkBench）和跨域迁移（双向平均+3.3分）均获正收益；而ADAS、AgentSquare、MASS的跨域迁移多为负。表明MANTA学到的是**可继承、可操作的结构知识**而非benchmark特定工作流。
- **Token效率**：MANTA总token消耗在所比较的多智能体系统中最低，meta-level操作仅占约12%，说明拓扑规划和修复的“元开销”不大。
- **修复形态洞察**：5个典型案例显示，拓扑演化不只是增加智能体或边——**串行化、重连通信、插入评论者**等非增长性修复同样重要，且修复由轨迹中可见的结构性失败决定，而非系统规模。

## 7. 优点

- **问题定义新颖**：首次明确提出“拓扑级自我改进”这一层次，并将拓扑作为推理时动态可变的系统组件，区别于离线工作流搜索。

- **状态管理设计巧妙**：智能体无状态、共享append-only存储、惰性读取，使得拓扑变异“无迁移、无丢失”，技术上具有可行性和可扩展性。

## 8. 不足与局限

- **实验规模有限**：每基准30题，评价集偏小；3次重复对高方差方法（如ADAS在PlanCraft上±13.4）统计稳定性不足。

- **公平性问题**：与AFlow/ADAS/AgentSquare/MASS等自动化设计方法的比较中，“匹配搜索预算”的具体实现细节未充分展开，难以保证完全公平。

- **泛化边界**：只覆盖“信息类”任务（检索、规划、工具、工作流、数学），未涉及具身控制、多模态交互、实时环境或大规模任务；长期剧本的迁移在跨域时幅度仍较小（+3.3），其通用性还需更多验证。
