## 摘要
基于大语言模型的图形用户界面（GUI）代理日益部署于移动、网页和桌面环境。然而，现有代理通常具有领域特异性，限制了部署和用户体验。这促使将专用模型整合为单一跨环境策略。权重合并直接合并领域专家，但在专家意见分歧时可能破坏可执行动作；而在线策略蒸馏（OPD）避免了相互冲突的教师监督，但仍在蒸馏过程中平等对待所有响应词元，忽视了动作词元是环境与代理之间唯一接口这一事实。为解决此问题，我们引入了MAGA，根据结构化动作重新分配训练信号。基于生成动作的正确性，它抑制不必要或无效的蒸馏信号，并专注于对错误动作的学习。此外，一种仅用于训练的提示优化了领域教师提供的监督信号，而不改变学生输入。在两种模型规模下，MAGA取得了最高的平均成功率，在8B规模下比最强基线高出2.0%，并与教师取得了几乎相同的平均性能。

## Abstract
Graphical user interface (GUI) agents based on large language models are increasingly deployed across mobile, web, and desktop environments. However, existing agents are typically domain-specific, limiting the deployment and user experience. This motivates the consolidation of specialized models into a single cross-environment policy. Weight merging directly merges domain-specific experts but can corrupt executable actions under expert disagreement, while on-policy distillation (OPD) avoids conflicting teacher supervision yet still treats all response tokens equally during distillation, ignoring that action tokens are the only interface between the environment and the agent. To address this, We introduce MAGA that re-allocates training signal according to the structured action. Based on the correctness of the generated action, it suppresses unnecessary or invalid distillation signals and focuses learning on erroneous actions. Besides, a training-only hint optimizes the supervision signal provided by domain-specific teachers without changing the student input. Across two model scales, MAGA achieves the highest mean success rate, outperforming the strongest baseline by 2.0% at 8B and achieves almost the same average performance with teachers.

# MAGA 论文总结

## 1. 核心问题与整体含义

- **背景**：基于大语言模型的 GUI（图形用户界面）代理已广泛部署于移动端、网页和桌面环境，但现有代理多为领域特定模型，部署复杂且跨域体验受限，因此希望将多个领域专用模型整合为单一跨环境策略。
- **现有方法缺陷**：
  - **权重合并**（Weight Soup、TIES）：直接融合各领域专家参数，在专家对同一输入做出不一致决策时，会破坏最终动作的可用性。论文实验显示，在高分歧样本上合并模型成功率比原专家下降 10%–24%。
  - **在线策略蒸馏（OPD）**：虽避免了教师冲突，但将响应视为平坦词元序列，对所有 token 平等施以蒸馏信号，忽略了 GUI 场景中真正与环境交互的只有短小的结构化动作部分。
- **核心问题**：如何设计一种蒸馏策略，使统一后的学生模型既能保留各领域教师能力，又能将训练信号集中到决定环境状态的动作 token 上。

## 2. 方法论

### 总体思路
MAGA 采用“样本级路由的在线策略蒸馏”（routed OPD）框架，并在此基础上从**学生侧**和**教师侧**同时改进训练信号分配。

### 核心概念
- 每个模型响应为 \( y=(r,a) \)，其中 \( r \) 为推理文本，\( a=(z,p_z) \) 为结构化动作：\( z \) 为动作类型，\( p_z \) 为该类型对应的参数（坐标、文本、URL、快捷键等）。
- 基础 token 级蒸馏优势：
  \[
  \hat{A}^{\text{OPD}}_t = \text{sg}[\log \pi_{T_d}(y_t|x,y_{<t}) - \log \pi_{\theta}(y_t|x,y_{<t})]
  \]

### 学生侧：条件式训练信号重分配
依据动作的正确性将训练样本分为三类，并为不同 token span 赋予权重 \( w_t \)（β=1）：

1. **规则 1：动作类型与参数均完全正确**
   - 该 rollout 已完全正确，不继续优化；整条响应（推理、类型、参数）的蒸馏信号全部置零。
2. **规则 2：类型正确但参数错误**
   - 保留推理 token 权重 1，动作类型和参数 token 权重放大为 \(1+\beta\)，使完整动作 span 获得强化监督，避免被长推理稀释。
3. **规则 3：动作类型错误（无论参数如何）**
   - 类型错误是最主要错误，且错误的类型会导致参数 schema 不匹配；因此仅放大类型 token（权重 \(1+\beta\)），推理保留权重 1，参数 token 被掩码（权重 0）。

### 教师侧：仅训练时提示（Training-Only Hint）
- 给路由到的领域教师输入末尾追加一个只包含参考动作类型的提示 \( h(z^*) \)（如 "Hint: the correct action is a {HINT} action"），从而使教师在给学生采样 token 打分时获得更可靠的引导。
- 学生的输入和输出完全不变，推理时也不引入该提示。
- 更新后的优势为：
  \[
  \hat{A}^{\text{hint}}_t = \text{sg}[\log \pi_{T_d}(y_t|P_T(x,z^*),y_{<t}) - \log \pi_{\theta}(y_t|P_S(x),y_{<t})]
  \]

### 最终目标函数
\[
\mathcal{L}_{\text{MAGA}}(\theta) = -\mathbb{E}_{d,x,y}\left[\frac{1}{|y|}\sum_{t=1}^{|y|} w_t \hat{A}^{\text{hint}}_t \log \pi_{\theta}(y_t|x,y_{<t})\right]
\]

训练时所有教师冻结，仅更新学生；禁用学生侧分配和教师侧提示后，等价于普通 routed OPD。

## 3. 实验设计

- **模型**：Qwen3-VL-2B 和 Qwen3-VL-8B；先在混合三域数据上中期训练获得共享学生 checkpoint，再对各领域独立 SFT 得到三个冻结教师。
- **Benchmark 与数据集**：
  - MobileWorld：117 个任务
  - OSWorld（全量）：369 个任务
  - WebVoyager 子集：140 个任务（14 个网站各 10 个）
  - 训练集为 343k 条专有工业数据：移动 93k、桌面 50k、Web 200k
- **对比方法**：Domain-specific Teacher、SFT、GRPO、Weight Soup、TIES、UI-MOPD（routed OPD 基线）
- **评估指标**：任务成功率（SR）；另定义了 **TNS（Teacher-Normalized Score）** 衡量学生保留各领域教师能力的比例，100% 表示平均与教师持平。
- **消融实验**：
  - 移除整个学生侧机制、移除教师侧 hint、两侧都移除（恢复普通 OPD）
  - 分别禁用三条学生侧规则（Rule 1/2/3）
- **额外分析实验**：
  - 900 个 held-out 样本（每域 300）的动作结果分布前后变化
  - 学生动作与各领域教师动作的匹配度分析
  - 推理 token 与动作 token 上学生-教师似然一致性对比
  - 仅纠正动作类型后参数恢复能力实验（136 个错误类型样本）
  - 高分歧空间动作样本（66 个 MobileWorld 任务）上对比 Weight Soup 的纠错能力

## 4. 资源与算力

- 论文明确说明：所有训练在 **32 块 H20 GPU** 上进行，训练 1 epoch；优化器 AdamW，学习率 1e-5，全局 batch size 128，最大序列长度 16,384，每个 prompt 生成 4 条 rollout，视觉参数保持冻结。
- **未明确说明**：每次训练的具体耗时、总 GPU 小时数、能耗等算力/成本信息。

## 5. 实验数量与充分性

- **实验数量较充分**：覆盖两个模型规模、三个平台基准、七个主要对比方法；包含完整的消融实验（学生侧、教师侧、三条规则分别移除），并结合 6 个定向分析实验，从行为来源、token 对齐、错误恢复、高分歧纠错等角度深入验证。
- **客观性与公平性**：
  - 所有蒸馏类方法共用相同的学生初始化、路由数据、冻结教师和 rollout 设置；
  - 每个 prompt 固定 4 条 rollout，β 固定为 1 且不逐域调参；
  - 使用固定评估样本、SR 为整数成功计数，TNS 能反映教师能力保留程度。
- **仍存在的局限**：
  - WebVoyager 仅用 140 任务子集，MobileWorld 任务量也较小，可能不足以完全代表完整基准；
  - 训练数据为专有数据且不可发布，外部可复现性受限；
  - 数据分布不均衡（Web 200k vs 桌面 50k），可能影响跨域均衡性；
  - 某些细分类别样本极少（如 URL 参数仅 5 例），部分结论统计支撑较弱。

## 6. 主要结论与发现

- **8B 规模**：MAGA 平均 SR 达 51.2%，比最强基线 UI-MOPD 高 2.0%，TNS 达 99.9%，与三领域教师平均性能几乎持平；在 OSWorld 和 WebVoyager 上超过对应教师，MobileWorld 比教师低 3.4%。
- **2B 规模**：平均 SR 和 TNS 均最高（25.3%、77.1%），虽在 WebVoyager 上略低于 Weight Soup，但综合表现最好。
- **高分歧样本**：权重合并（Weight Soup）在 66 个高分歧样本上准确率仅 71.2%，MAGA 将其提升至 84.8%，纠正了 10 个错误且仅引入 1 个新错误。
- **错误来源变化**：训练后完全正确动作占比从 42.2% 提升到 63.2%（+21.0%），类型错误下降 16.3%，参数错误下降 4.7%。
- **行为来源**：61.5% 的 student 动作与对应领域教师一致，仅 14.8% 与其他领域教师一致；3.0% 的动作虽不与任何教师匹配但实际上是正确的新动作，说明学生具备一定的新行为生成能力。
- **token 一致性**：动作 token 上学生与教师的似然一致度比推理 token 平均高 +0.072，验证了面向动作 token 的监督设计的合理性。
- **类型纠正实验**：仅将错误动作类型替换为正确类型，模型可自动恢复 68.4% 的错误动作参数（坐标类恢复 87 例中的 57 例），说明许多参数错误根因在类型判断。

## 7. 优点

- **问题定位准确**：清晰指出了权重合并与普通 OPD 在 GUI 场景下的结构性缺陷，并用数据证实（高分歧样本性能下降、动作 token 占比仅 3.9%–7.1%）。
- **方法简洁有效**：学生侧按动作语法做信号重分配 + 教师侧加仅训练提示，无需改变学生推理接口，推理零额外开销。
- **规则设计具有可解释性**：三种训练规则与动作错误类型一一对应，逻辑清晰，且消融验证了每条规则的必要性。
- **评估体系较完善**：除 SR 外引入 TNS，并设计多组微观分析实验，可深入理解模型行为来源和改进机制。
- **跨平台覆盖广**：同时覆盖移动、桌面、网页三类 GUI 环境，且训练使用大规模真实工业数据，接近生产场景。

## 8. 不足与局限

- **数据不可公开**：训练数据受保密协议约束无法发布，严重影响可复现性和社区验证。
- **模型架构覆盖窄**：仅在 Qwen3-VL 2B/8B 上验证，未测试其他 VLM 架构或更大/更小规模。

- **算力信息不完整**：未报告训练时长和总计算成本，难以评估方法的实际资源开销。
- **部分统计对比缺乏显著性检验**：论文仅在分析协议中提到 bootstrap 误差估计，但主结果表格未给出置信区间或显著性检验结果，点估计差异的显著性不够明确。
