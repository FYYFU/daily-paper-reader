## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题解决能力。然而，现有系统通常将通信拓扑视为固定设计选择或离线优化目标。我们提出MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自我进化。在执行前，MANTA根据先前的结构经验初始化任务条件化拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在涵盖信息检索、工具使用、规划、工作流执行和数学推理的五个基准上评估MANTA与代表性的单智能体和多智能体基线。MANTA取得了74.0的最高平均分，比最强基线高出5.8个百分点，并在PlanCraft上获得最佳结果。这些结果表明，推理时的自我改进可以扩展到协作本身的结构。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

- 现有方法存在一个关键缺口：**拓扑通常在设计与离线优化阶段被固定**（如 AFlow、ADAS、AgentSquare、MASS 等自动化设计框架均在执行前确定工作流），一旦任务执行开始便不再改变。推理时的自我改进（如输出、提示词、推理轨迹、记忆等层面的自适应）尚未延伸到“多智能体如何组织与通信”这一协作架构层面。

**核心问题**

> 多智能体系统能否在解决每个任务的过程中，同时改进其自身的通信拓扑？

**整体含义**

- 论文将拓扑层面（Topology，L6）定位为自我改进的新层级，位于输出（L0）、提示词（L1）、推理轨迹（L2）、技能/工具（L3）、记忆（L4）、智能体角色（L5）之上，权重（L7）之下。
- 核心主张是：**推理时的自我改进可以延伸到协作架构本身**，拓扑不是固定的设计选择，而是可以在执行过程中被系统自身调整的对象。

## 2. 论文提出的方法论

**核心思想**

MANTA（Multi-Agent Network Topology Adaptation）采用双层嵌套架构：目标多智能体系统负责推理、工具调用与消息交换；编排层负责选择智能体、通信链接与信息可见性，并在执行中出现结构性缺陷时进行有界修复。整个过程不依赖基准答案，仅依据可观察的协作过程信号。

**关键组件**

- **拓扑规划器（Topology Planner）**：在任务执行前，基于任务分析与长期经验记忆（long-term playbook）生成任务条件化的初始拓扑方案（交互模式、智能体数量、可选验证器或嵌套子组）。确定性代码将其扩展为完整拓扑并校验结构约束。
- **轨迹审计器（Trace Auditor）**：执行轮次结束后，扫描结构化中间产物、工具调用记录、中继数据包、置信度、未解决问题与证据可见性，输出过程性风险标记（如 premature_consensus、duplicate_state_mutation、missing_validator 等），**不判断答案正确性**。审计器包含确定性异常分类器与开放式 LLM 组件。
- **控制器（Controller）**：根据审计结果决定是否终止、直接生成最终答案，或允许一次有界拓扑修复（每次运行最多 1 次突变、每次突变最多 3 个操作）。
- **技能反射器（Skill Reflector）**：每 N 次运行后，根据仅含过程信号（非基准真值）的运行摘要重写长期 playbook 中的经验教训。
- **双时间尺度记忆**：短期 playbook 记录当前运行内每轮的拓扑、审计标记、修复建议与决策；长期 playbook 跨运行累积“任务特征与过程风险 → 拓扑选择”的通用原则。

**拓扑表示与突变算子**

- 拓扑规格定义版本化的多智能体系统，每个智能体具有结构角色（coordinator/worker/verifier/debater/voter）与阶段角色（worker/critic），可附带领域人设与工具权限。
- 支持嵌套分组（智能体可将子任务委托给子组并综合报告）、直接通信边、上下文策略（信息可见性）。
- 突变算子共 6 种：`add_agent`、`expand_agent_to_group`、`set_group_pattern`、`add_edge`/`remove_edge`、`set_context_policy`。另有针对检索密集型任务的确定性“检索收缩”路径（不经过规划器）。
- 所有突变经确定性代码校验（组成员唯一性、标识符与角色合法性、嵌套无环、模式合法、智能体预算），非法提议被拒绝。

**关键设计细节**

- 智能体无状态，所有对话状态存于共享的追加式存储中（数据包存储、证据账本、轮次候选列表）；拓扑突变仅需将上下文控制器重新指向新规格，无需迁移或丢失任何状态。
- 信息可见性在代码层面强制（读取时依据策略过滤），而非依赖提示词约束。
- 存在纪律性护栏：工具调用去重、停滞搜索检查、故障熔断器、强制最终答案等。

## 6. 论文的主要结论与发现

**主要结果**

- MANTA 在 5 个基准上的平均得分 **74.0**，比最强基线（ADAS，68.2）高出 **5.8 个百分点**，并在 PlanCraft 上取得最好的 76.7 分。
- MANTA 在所有基准上都优于 Single Agent（59.3），提升幅度达 14.7 个百分点。
- 相比静态多智能体工作流（最佳 66.2）和自适应设计方法（最佳 68.2），MANTA 均有显著优势。

**消融结论**

- 初始拓扑规划贡献最大（移除后从 71.7 降至 57.5，降 14.2 点）。
- 执行期拓扑修复次之（移除后降至 60.8，降 10.9 点）。
- 长期 playbook 更新与存在提供额外但较小的增益（各降约 4～5 点）。

**突变预算结论**

- 所有基准随预算增加而改善；第一次突变机会带来最大增益，后续突变增益递减。

**迁移性结论**

- MANTA 在域内迁移（+3.3 点）和跨域迁移（+3.3 点）均为正收益；而 ADAS（-3.3）、AgentSquare（-13.3）、MASS（-58.3）在跨域迁移中均为负收益或大幅退化，说明 MANTA 的 playbook 学到的是可继承的通用结构知识而非特定基准的工作流。

**审计与修复结论**

- 无修复标记的运行正确率 83.2%，有标记的运行正确率 62.5%，相差 20.7 个百分点——过程信号对答案可靠性具有预测价值。
- 审计器识别出 117 个错误运行中的 75 个；WorkBench 上 F1 达 0.78（空分支和重复状态变更留下清晰过程证据）。
- 151 次修复中，60.9% 减少了过程标记数量，59.6% 的命名修复目标在下一轮审计中消失；修复后的运行 69.5% 产出正确最终答案。
- 关键洞察：**拓扑演化不一定是增加智能体或边**——序列化、重新布线和插入批判者都是有效的修复手段。五种代表性修复中只有分支扩展使系统变大。

**效率结论**

- MANTA 是所有多智能体系统中 token 消耗最低的（77,652/轮），元层面操作仅占约 12%，说明针对性拓扑规划与修复不会带来显著 token 开销。

## 7. 优点

1. **问题定义新颖**：首次系统性地将“通信拓扑的推理时自我改进”形式化为独立研究问题，补充了自我改进层级的 L6 层。
2. **方法设计精巧**：
   - 审计器只使用过程信号、不接触基准真值，保证方法的通用性与诚实性；

   - 双时间尺度记忆（短期+长期）兼顾了局部修复与跨运行知识积累；
   - 智能体无状态设计使拓扑突变“便宜且无损”——仅需重定向上下文控制器，无需迁移状态。
3. **实验全面**：覆盖面广（5 个异构基准）、基线丰富（14 种基线）、消融完整（4 个变体）、视角多样（性能、token 效率、迁移性、审计质量、算子使用）。
4. **分析深入**：对修复行为的定性案例分析（分支扩展、验证器添加、序列化、通信重连、批判者插入）揭示了拓扑演化的丰富形态，超越了“增加智能体”的简单直觉。
5. **token 效率突出**：推理时自适应不但没有增加开销，反而将 token 消耗降至所有多智能体系统中最低。

## 8. 不足与局限

1. **审计器的预测精度有限**：审计标记的精度仅 0.38（即 37.5% 的标记最终对应错误答案），意味着大量“标记但正确”的误报；在 BrowseComp 和 StableToolBench 上误报率高达 72%～90%。作者也承认两个检测模式（消息压缩丢失、工具错误级联）不具有正确性区分力。
2. **无人工标注验证**：论文没有人工标注“轨迹中是否真实存在协作缺陷”，因此精度/召回指标不能直接解读为过程缺陷检测的真实分数——作者明确声明了这一点。
3. **推理类基准上的审计价值有限**：审计器在 PlanCraft 和 MATH 上极少提出修复（11/90 和 20.5/90），因为错误推理往往没有可观察的协调症状。这意味着 MANTA 的优势主要集中在有明确过程信号的检索/工作流任务上。
4. **样本规模偏小**：每个基准仅 30 题 × 3 次运行，统计功效有限；迁移实验中每个方向仅 1 组 30 题的对比，未报告多次重复迁移运行的方差。
5. **单一骨干模型**：所有实验仅使用 Gemma 4 31B，MANTA 的结论是否适用于更强/更弱的模型（如 GPT、Claude 系列）尚不明确。
6. **每轮多次重复的成本被低估**：自一致性采样和自我反思等基线的实验设置可能未与 MANTA 完全对齐（如 MANTA 修复后仅多运行一轮，而 Self-Refine 可迭代多轮）。
7. **“过程干净”不等于“答案正确”**：即使达到决策级共识，仍有 14.2% 的错误率；多智能体可能就同一个错误答案达成共识而无任何可观察异常（作者已承认）。
