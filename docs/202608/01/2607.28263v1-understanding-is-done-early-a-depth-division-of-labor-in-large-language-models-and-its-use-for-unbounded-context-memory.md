## 摘要
Transformer的深度并非均匀使用：较低层和中间层构建语义表示，而较高层则逐渐特化这些表示以用于预测。我们将这种分工转化为CoMem（理解记忆），它仅通过中间层写入每个上下文块，检索固定数量的缓存残差状态，并在生成的组合上重新计算查询条件化的上层。对于固定的检索预算，模型端的读取计算和内存与存储的上下文长度无关。我们在统一的无需聊天模板的协议下评估了一个持续训练的Qwen3-8B基础语言模型。主干网络被冻结；旗舰版本仅在普通PG19上训练了秩为32的自蒸馏LoRA，我们单独报告了一个无适配器的分支。CoMem在RULER上达到97.05，在LoCoMo上达到38.27，而全上下文KV-Direct为34.59；对话记忆优势在对话簇重采样和独立评判下依然存在。在其他长上下文和长文档任务上的结果既展示了有界检索的优势，也揭示了其窗口内压缩代价。受控深度扫描显示，更深的缓存降低了每次查询的重计算量，但带来了保真度损失，而自蒸馏在很大程度上修复了这种损失。在一个单独的NVIDIA H20上的128k无适配器效率控制实验中，CoMem使用18.26 GB而非89.36 GB，并实现了7.83倍的预填充加速。这些结果表明，长上下文记忆可以沿层轴而非仅沿token轴进行组织。

## Abstract
Transformer depth is not used uniformly: lower and middle layers build semantic representations, while upper layers increasingly specialize them for prediction. We turn this division of labor into CoMem (Comprehension Memory), which writes each context chunk only through an intermediate layer, retrieves a fixed number of cached residual states, and recomputes the query-conditioned upper layers over the resulting pack. For a fixed retrieval budget, model-side read compute and memory are independent of stored-context length. We evaluate a continued-trained Qwen3-8B base LM under a unified chat-template-free protocol. The backbone is frozen; the flagship trains only a rank-32 self-distillation LoRA on plain PG19, and we report an adapter-free arm separately. CoMem reaches 97.05 on RULER and 38.27 on LoCoMo versus 34.59 for full-context KV-Direct; the dialogue-memory advantage survives conversation-cluster resampling and an independent judge. Results on additional long-context and long-document tasks expose both the benefits of bounded retrieval and its in-window compression tax. Controlled depth sweeps show that deeper caching lowers per-query recomputation but incurs a fidelity loss that self-distillation substantially repairs. In a separate adapter-free efficiency control on an NVIDIA H20 at 128k, CoMem uses 18.26 GB rather than 89.36 GB and achieves a 7.83x prefill speedup. These results show that long-context memory can be organized along the layer axis, not only the token axis.

## 二、论文提出的方法论

**核心思想：**
- Transformer 深度并非均匀使用：中低层（约 0.45L 处）即可获得语义内容，上层则更多是查询条件化的预测特化。因此，缓存中间层的残差状态，而非缓存全深度 KV，可以在保持语义的同时极大减少存储。

**CoMem 三大步骤：**

1. **Write（写入）**：
   - 将上下文划分为不重叠的 512-token 块，每个块从位置 0 开始，仅通过前 j 层（旗舰版 j=12/36），将残差张量 h_j 存入外部存储并按键索引。
   - 写操作成本线性于上下文长度，但只需执行 j 层。

2. **Select（选择）**：
   - 使用迭代 BM25 检索 top-12 个相关块（约 6.5k tokens），跳宽为 4，自动执行 3 轮前沿扩展并去重。

3. **Read（读取）**：
   - 将 [BOS；选中的 h_j；查询 h_j] 打包，使用全新的连续 RoPE，在层 [j:L] 上执行完整因果交叉块注意力。
   - 由于 k、块大小和查询长度固定，**读取工作集与存储上下文长度无关**。

**关键技术细节：**

- **存储效率**：每个 token 仅缓存一个残差向量（8 KB），而全 bf16 KV 需要 144 KB/token，压缩比为 1/18。
- **j=0 等价性**：当 j=0 时，CoMem 等同于选择性全量前向，与同包上的标准前向最大 logit 差 <10⁻⁴。
- **自蒸馏训练**：
  - 教师为冻结的 j=0 模型，学生在 j=12 处匹配教师 top-64 logit 支持上的分布。
  - 目标函数为双向 KL：L = 0.6·KL(p‖q) + 0.4·KL(q‖p)，无附加交叉熵项。
  - 仅训练层 12–35 上的秩-32 LoRA（α=64），数据为 PG-19 的 2048-token 窗口，无任何任务监督或检索参与。

## 六、论文的主要结论与发现

1. **深度是有价值的复用轴**：长上下文记忆可以沿层轴组织，而非仅沿 token 轴。内容深度（≈0.45L）随模型规模近似不变，可读深度随规模加深。
2. **有界检索优于全上下文或纯近因**：在相同约 6.5k token 预算下，CoMem 在 RULER 上保持近 100 的准确率，而 StreamingLLM 从 85 跌至 2。
3. **更深的缓存降低查询成本但损保真度**：j=12 相比 j=0 减少 29% 读取时间，但冻结保真度下降；自蒸馏可在不更新主干的情况下大幅修复（+13.75 LoCoMo 分）。
4. **选择（而非保真度）是长距离瓶颈**：Oracle 选择在 needle 任务上达到 100%，表明检索质量是关键限制。
5. **交叉块注意力对多事实消歧必要**：块对角复用使 multikey 检索损失 36/62 分（8k/16k）。
6. **跨规模/架构泛化**：在 Qwen3 0.6B–32B 和两个 MoE 后端（Qwen3-30B-A3B、Hunyuan Hy3 80 层）上均验证了方法可行性。
