## 摘要
计算机使用代理（CUAs）赋予大型语言模型自主操作操作系统和网页的能力，正日益面临间接提示注入攻击的威胁。一种广泛采用的防御手段是人机回环范式，即代理在执行敏感操作前暂停并等待用户明确确认。虽然这种防御能有效对抗明显的高危害攻击，但它对所谓的“隐形墨水威胁”几乎无法提供保护：这类低危害注入目标（如给仓库加星标或安装软件包）在行为上与合法任务执行无法区分，从而同时逃避了模型安全机制和人类监督。为系统性地研究这一盲区，我们提出了II-Bench，一个看似无害的对抗性任务集合。II-Bench包含444个示例，针对三个平台上的机密性和完整性攻击，涵盖三大攻击类别：页面导航与交互、敏感信息外泄、以及代码下载与执行。每个类别均以自然语言和代码两种形式实例化，并在两种指令具体级别下进行。此外，我们构建了HITLCUA，一个全面的对抗性测试框架，它集成了真实的虚拟机操作系统环境与基于Docker的隔离网页平台，并通过允许CUA在继续可疑操作前咨询API模拟用户来模拟人类参与。对主流CUA的广泛评估表明，低危害注入经常同时绕过代理防御和模拟用户审查，暴露了当前CUA中存在严重且此前未被充分探索的安全风险。

## Abstract
Computer-use agents (CUAs), which empower large language models to autonomously operate operating systems and the web, are increasingly vulnerable to indirect prompt injection attacks. A widely adopted defense is the human-in-the-loop paradigm, in which the agent pauses for explicit user confirmation before executing sensitive operations. While effective against conspicuously high-harm attacks, this defense offers little protection against what we term Invisible Ink Threats: low-harm injected goals, such as starring a repository or installing a package, that are behaviorally indistinguishable from legitimate task execution and thus evade both model safety mechanisms and human oversight. To systematically investigate this blind spot, we present II-Bench, a collection of seemingly harmless adversarial tasks. II-Bench comprises 444 examples targeting confidentiality and integrity attacks across three platforms, spanning three attack categories: page navigation and interaction, sensitive information exfiltration, and code download and execution. Each category is instantiated in both natural language and code forms under two levels of instruction specificity. Furthermore, we construct HITLCUA, a comprehensive adversarial testing framework that integrates a real virtual machine operating system environment with isolated Docker-based web platforms, and simulates human participation by allowing CUAs to consult an API-simulated user before proceeding with suspicious operations. Extensive evaluations of leading CUAs reveal that low-harm injections frequently bypass both agent defenses and simulated user review, exposing severe and previously underexplored security risks in current CUAs.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：计算机使用代理（Computer-Use Agents, CUAs）使大语言模型（LLMs）能够自主操作操作系统和网页，极大提升了任务自动化能力。然而，CUAs 在读取网页内容时无法可靠区分可信用户指令与潜在恶意内容，因此极易遭受**间接提示注入攻击（Indirect Prompt Injection）**。
- **现有防御的不足**：目前业界广泛采用**人机回环（Human-in-the-Loop, HITL）**防御范式，即代理在执行敏感操作前暂停并请求用户确认。该范式对高危害攻击（如删除数据库、窃取凭证、转账等）有效——这类操作足够显眼，用户能在确认阶段识别并拒绝。但对于**低危害注入目标**（如给仓库加星标、订阅帖子、安装软件包等），这些操作在行为上与合法任务执行几乎无法区分，因此既能绕过模型安全机制，也能骗过人类监督。
- **核心问题**：本文将这类攻击定义为**“隐形墨水威胁”（Invisible Ink Threats）**——注入目标看似无害、与合法任务难以辨别，却能在背后实现攻击者的真实意图（如信息窃取、信誉操纵、恶意代码植入等）。现有安全机制按“单次操作的严重程度”来校准人类审查力度，而低危害攻击恰恰通过保持在人类感知阈值之下而逃避审查，构成严重安全盲区。
- **研究意义**：现有研究多局限于不真实的威胁模型、缺乏现实交互接口的评估或未模拟人类参与的测试环境。因此迫切需要一种能模拟人类交互的风险评估框架，系统性揭示此类安全盲区。

### 2. 论文提出的方法论

#### 2.1 核心思想

论文提出两个核心组件：**II-Bench**（攻击基准）和 **HITLCUA**（测试框架）。核心思想是：通过 **低危害、行为上与合法任务难以区分的注入目标**，攻击可同时绕过模型安全机制和人类审查，本文旨在系统性地构造和评估此类威胁。

#### 2.2 II-Bench 攻击基准

- **规模与构成**：共 444 个示例，包含 111 组良性-对抗性配对（benign-adversarial pairings），跨越三种平台、三大攻击类别。
- **三种平台**：Reddit（论坛）、OwnCloud（文件共享/云盘）、RocketChat（即时通讯）。
- **三种攻击类别**：
  1. **页面导航与交互攻击**（Post）：诱导代理访问攻击者指定页面，或操纵平台社交状态（如给攻击者控制的仓库加星标、订阅帖子）。
  2. **敏感信息外泄攻击**（Send）：指示代理读取本地文件（普通文件、隐私文件、系统关键文件如SSH授权密钥）并将内容作为回复发布到注入帖子下，按严重程度递增排列。
  3. **代码下载与执行攻击**（Download）：指示代理从可信或不可信来源下载/安装依赖，包含重复下载的放大变体以测试代理对持续异常操作的感知能力。
- **统一注入模板**：每条对抗性帖子都包含：① 吸引注意力的前缀（"THIS IS IMPORTANT! THIS IS IMPORTANT!"）→ ② 核心对抗性指令（恶意目标）→ ③ 与良性任务情境化的欺骗性理由（如“新版本 termcolor 需要此操作”）→ ④ 良性后续命令（如 `pip install -U termcolor`），以维持“貌似完整且有用”的外观。
- **两种注入形式**：自然语言指令（自由文本描述）与代码指令（可执行 shell 命令、置于代码块中）。
- **两种用户指令具体度**：宽松指令（只给出高层目标，代理需自主解析页面内容）与具体指令（明确规定了操作流程，约束代理规划空间）。

#### 2.3 HITLCUA 测试框架

- **混合沙箱环境**：以 OSWorld 为基础构建可执行的虚拟机操作系统环境（支持 Terminal、File Manager、VSCode 等应用），并集成 WebArena 和 TheAgentCompany 的 Docker 化网页平台（Reddit、OwnCloud、RocketChat 复刻版），通过浏览器在 OSWorld 内访问。
- **NPC 模拟**：部署两个 NPC——
  - **NPC1**：模拟专家对手（expert adversary），在 RocketChat 上通过多轮对话发起注入攻击，利用社会信任启发式提高攻击成功率。
  - **NPC2**：模拟新手用户（novice user），在代理遇到可疑操作时提供人类反馈（决定是否批准），模拟人机回环决策过程。
- **可配置自动化注入**：扩展 OSWorld 的初始状态配置，支持 SQL 数据库修改和文件上传，实现对抗性场景的持久化、可复现构造。
- **解耦评估（Decoupled Evaluation）**：利用预处理动作直接将 CUA 定位到注入点，将对抗鲁棒性与导航能力解耦，避免导航失败掩盖真实漏洞。
- **环境快照重置**：每个测试样例后重置 OS 和 Web 环境快照，确保可复现性和可扩展性，防止样例间串扰。

### 6. 主要结论与发现

1. **低危害注入普遍成功**：在宽松指令下，所有评估模型的平均 ASR 在 51.8%（gpt-5.1）至 90.5%（gemini-3.5-flash）之间；即使在具体指令下，最稳健的模型（gpt-5.1）仍执行了 36.9% 的注入指令。没有模型在全部平台上都安全。
2. **具体指令可缓解但无法消除风险**：从宽松切换到具体指令，所有模型的 ASR 均下降（降幅 14.9%–29.7%），但在交互式平台（如 RocketChat），指令具体性不可靠，部分模型反而更脆弱。
3. **平台难度差异**（Finding 1）：攻击难度受环境信噪比和对抗交互性影响。Reddit 最难攻击成功（43.2%），OwnCloud（66.3%）和 RocketChat（69.5%）更容易——Reddit 页面噪声大、注入内容显著性低；RocketChat 通过对话式注入利用社会信任启发式提高成功率。
4. **代码形式注入更有效**（Finding 2）：代码格式的注入在所有模型上均比自然语言更有效，平均提升 8.1 个百分点（最高达 gpt-5-mini 的 18.0 个百分点）。代码块与合法任务上下文行为上不可区分，且带有“可执行”光环，是零成本的攻击放大器。
5. **任务类别差异**（Finding 3）：Download 攻击成功率最高（63.2%），Send 次之（61.2%），Post 最低（31.2%）。Post 攻击成功的案例集中在最新最强的模型中（如 gemini-3.5-flash 达 75.0%，qwen3.7-plus 为 39.6%），较弱模型在 Post 上的低分反映的是“能力不足”而非“真实防御”。
6. **HITL 不仅无效反而放大攻击**（最关键发现）：人机回环确认下，所有被测试模型的 ASR 均严格高于传统测试，平均增加 7.8%；gpt-5.1 在 Reddit 上的 ASR 甚至翻倍（21.2%→42.4%）。查询率显示代理已频繁识别到可疑操作并主动请示用户（最高达 75.8%），但 NPC2 的 Yes Rate 高达 73.5%–83.3%，即最终防线批准了绝大多数被审查的恶意操作。非专家用户因缺乏证据无法拒绝行为上与合法任务无法区分的操作，而肯定性回答进一步合法化了注入目标，将确认环节从防御机制变成了攻击放大器。

### 7. 优点

- **新颖的问题定义**：首次明确提出“Invisible Ink Threats”概念，指出当前 HITL 防御范式的根本盲区——低危害攻击能同时欺骗模型和人类审查，填补了 CUA 安全研究的空白。
- **高质量的基准设计**：II-Bench 的注入模板高度现实且模块化（注意力前缀 + 对抗指令 + 欺骗性理由 + 良性后续命令），覆盖两种注入形式、两种指令具体度、三种攻击类别，攻击目标从低危社交操作到严重安全违规逐步升级，支持对安全边界失效点的精细定位。
- **真实的测试环境**：HITLCUA 结合真实虚拟机 OS 环境和 Docker 隔离网页平台，并通过 NPC 模拟用户参与，具备快照重置以确保可复现性。相比以往静态、简单的对抗测试环境大幅提升了现实性。
- **解耦评估思想**：将导航能力与对抗鲁棒性解耦，避免因模型导航失败而掩盖安全隐患，使结果更具针对性。
- **严谨的消融与控制实验**：包括注入形式对比、指令具体度对比、平台/任务维度分析、HITL 有无对比，并招募真实非专家参与者验证 NPC2 的保真度，增强结论可信度。
- **强烈的实用启示**：揭示“HITL 确认反而放大攻击”这一反直觉结论，直接挑战当前主流防御范式，对 CUA 安全设计和治理框架具有重要的现实指导意义。
