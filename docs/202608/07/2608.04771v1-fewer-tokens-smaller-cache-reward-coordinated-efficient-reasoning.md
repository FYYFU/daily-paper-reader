## 摘要
大型推理模型（LRM）通过长思维链（CoT）推理在复杂任务上表现出色，但其冗长的中间步骤会导致严重的过度思考，从而增加推理成本。KV缓存压缩是一种常见解决方案，然而现有的面向推理的方法在轨迹上应用统一策略，且仅根据从缓存中移除的内容来判断压缩效果。两个观察结果指向了另一方向。首先，推理状态对上下文丢失的容忍度在轨迹中有所变化，过程奖励能够跟踪这一点：在高奖励步骤删除令牌比随机删除相同预算更能保持准确性。其次，压缩在生成端并非没有代价，因为较小的缓存会导致模型生成更多令牌，部分抵消了节省。这些共同促使在单一过程奖励下协调两端。我们提出ReCo（奖励协调压缩），一种逐步框架，其中轻量级过程奖励估计器对每个完成的步骤进行评分，并驱动三个组件：（1）奖励自适应KV缓存压缩，在高奖励步骤更积极地缩减保留缓存，在低奖励步骤则减少压缩；（2）对反思令牌的奖励带惩罚，以抑制冗余生成；（3）基于置信度的提前停止，在推理可靠时触发。在三个推理模型和六个基准上，与完整CoT相比，ReCo将生成令牌减少了37%-65%，端到端延迟降低了2.08倍-2.35倍，同时大体保持了准确性。

## Abstract
Large Reasoning Models (LRMs) excel on complex tasks through long chain-of-thought (CoT) reasoning, but their lengthy intermediate steps cause severe overthinking that inflates inference cost. KV-cache compression is a common solution, yet existing reasoning-oriented methods apply a uniform policy across the trajectory and judge compression only by what it removes from the cache. Two observations point the other way. First, a reasoning state's tolerance to context loss varies along the trajectory, and process reward tracks it: deleting tokens at high-reward steps preserves accuracy far better than deleting the same budget at random. Second, compression is not free on the generation side, since a smaller cache leads the model to generate more tokens, partly canceling the saving. Together these motivate coordinating both sides under a single process reward. We propose ReCo (Reward-Coordinated Compression), a step-wise framework in which a lightweight process-reward estimator scores each completed step and drives three components: (1) reward-adaptive KV-cache compression that shrinks the retained cache harder at high-reward steps and less at low-reward ones, (2) a reward-banded penalty on reflection tokens that curbs redundant generation, and (3) confidence-based early stopping that triggers when the reasoning is reliable. Across three reasoning models and six benchmarks, ReCo reduces generated tokens by 37%-65% and end-to-end latency by 2.08x-2.35x over Full CoT, all while largely preserving accuracy.

## 1. 论文的核心问题与整体含义（研究动机和背景）

大型推理模型（LRM）通过长思维链（CoT）推理在数学、代码和科学问题求解等复杂任务上表现出色，但这种能力以高昂的推理成本为代价——模型经常“过度思考”，即使对简单问题也会生成长达数千甚至上万 token 的推理链，造成严重的 token 开销、延迟增加和计算负担。

现有缓解手段——KV 缓存压缩——虽然能降低内存和注意力计算成本，但作者指出了两个被现有方法忽略的关键问题：

- **问题一：统一的压缩策略忽视了推理阶段的差异。** 推理轨迹中不同步骤对上下文丢失的容忍度是不同的。高奖励（on-track）的推理步骤状态稳固，删除部分上下文影响不大；而低奖励（仍在探索）的步骤信息密度高、状态脆弱，压缩容易破坏推理链。现有方法（如 R-KV、RPC）对整条轨迹施加统一压缩策略，没有体现这种阶段差异。

- **问题二：KV 压缩会诱发更长的生成。** 压缩缓存后，模型往往会生成更多 token（实验中最多 79.8% 的问题在压缩后生成更长输出），这部分额外生成部分抵消了压缩带来的收益，甚至可能“回火”。

**核心主张：** KV 缓存压缩不能作为一种孤立手段，必须与生成控制协同进行；过程奖励（process reward）可以提供统一的信号来同时指导压缩与生成，实现准确率与效率的更好平衡。

## 2. 论文提出的方法论

### 2.1 核心思想

ReCo 提出一种**步级（step-wise）**框架，以推理步骤（按换行符拆分）为控制单元，用轻量级过程奖励估计器给每个完成的步骤打分（0~1），并用同一个分数驱动三个组件：

1. **奖励自适应 KV 压缩** —— 高奖励步骤压缩更狠，低奖励步骤保留更多。
2. **奖励带反思惩罚** —— 高奖励步骤抑制“Wait”“Hmm”等反思 token 的生成。
3. **基于置信度的早停** —— 奖励持续偏高且答案置信度达标时终止推理。

### 2.2 关键技术细节

**（1）过程奖励估计器**

- 步骤划分：将思维链 C 按 `\n` 拆分为步骤 `c₁, ..., c_T`。
- 奖励打分：采用 **Pilot**（30M 参数），是从 Skywork-o1-Open-PRM-7B 蒸馏得到的轻量级 PRM，`v_i = Pilot(c≤i)`。由于动机实验和最终方法共用同一奖励家族，形成了“观察 → 方法”的一致性链条。

**（2）奖励自适应 KV 压缩**

- 触发条件：缓存增长超过 S 个 token 后执行压缩。
- 保留率公式：  
  `λᵢ = λ_base − δ · (vᵢ − v̄) / (v_max − v_min)`  
  即根据当前步骤奖励相对轨迹内均值/极值的位置，在 `[λ−δ, λ+δ]` 内调整保留比例。高奖励 → 更低保留率（更激进压缩）；低奖励 → 更高保留率。

- Token 选择：保留最近 w 个 token（查询窗口）以及按注意力得分最高的 mᵢ 个 token。注意力决定“保留什么”，奖励决定“保留多少”。

**（3）奖励带反思惩罚**（Reflection Control）

- 构造反思 token 集合 R（如“Wait”“Hmm”“Alternatively”及其分词变体）。
- 根据步骤奖励划分三个区带（`τℓ = 0.4`，`τh = 0.8`）：
  - 低奖励（v ≤ τℓ）：不惩罚，自由探索。
  - 中奖励：半惩罚（β/2）。
  - 高奖励（v ≥ τh）：完全惩罚（β）。
- 实现方式：在解码时对反思 token 的 logit 直接减去惩罚值，纯解码层面操作，无额外推理开销。

**（4）基于置信度的早停**

- 条件：奖励连续两步落在 top band（v ≥ τh）。
- 操作：插入结束思考提示，诱出候选答案 a。
- 判断：计算答案困惑度 `PPL(a)`；若 `PPL(a) ≤ τp (=1.1)` 则停止并输出，否则丢弃候选、继续推理。
- 设计意图：奖励衡量“推理路径的可靠性”，PPL 衡量“模型对答案的置信度”，两者互补，避免“自信但错误”的提前停止。

## 6. 论文的主要结论与发现

### 核心发现

1. **过程奖励能可靠指示压缩容忍度。** 删除高奖励步骤的 token 比随机删除同一预算在准确率上高出 3.5~6.5 个点，证实高奖励状态更耐压缩。

2. **KV 压缩会导致长度膨胀。** 在 25% 压缩率下，R-KV 使 Qwen-7B 的 MATH-500 平均生成长度增加 38.8%，使 Llama-8B 增加 79.0%；超过一半的问题在压缩后生成了更长输出（最高 79.8%）。因此压缩不能只看缓存端收益。

3. **ReCo 在效率与准确性上均优于现有方法。**
   - **Token 效率：** 相比 Full CoT，生成 token 减少 37%（Llama-8B）、65%（Qwen-7B）、46%（Qwen3-8B）；而纯 KV 压缩方法（SnapKV/R-KV/RPC）反而增加了 token 数量。
   - **延迟：** 端到端加速 2.08×（Llama-8B）、2.35×（Qwen-7B）、2.18×（Qwen3-8B）。
   - **准确性：** 平均准确率仅下降 2.4~2.7 个点（如 Llama-8B 上 62.8% → 60.2%），是所有压缩方法中损失最小的；在 AIME25 等高难度基准上明显优于纯 KV 压缩方法（33.3% vs. ≤20%）。
   - **内存：** 峰值显存降至 17.92 GB，比 Full CoT 降 37.7%，优于 R-KV（20.7 GB）和 SAT（26.9 GB）。

### 消融结论

- 三个组件互补而非冗余：单独 KV 压缩在难题上 token 膨胀严重（AIME25 达 12.8k vs. ReCo 8.6k）；单独反思控制或早停则准确率下降。三者合一方能同时优化准确率与成本。

## 7. 优点

1. **问题洞察深刻、动机扎实。** 两个核心观察（高奖励步骤更耐压缩、KV 压缩引发长度膨胀）都有直接实验支撑，而且是先验证再建模，逻辑链完整。
2. **统一的协调机制。** 用单一过程奖励同时驱动压缩强度、反思抑制和早停判断，避免了多个控制信号之间的不一致，设计简约而优雅。
3. **轻量高效。** Pilot 仅 30M 参数，额外开销占比约 4%；压缩选择只依赖注意力分数，没有引入沉重的计算模块；反思惩罚在 logits 层面操作，零额外前向传播。
4. **实验覆盖面较广。** 多模型（两种架构、三种规模）、多难度（GSM8K 到 AIME25）、多维度（准确率/tokens/延迟/显存）评估，并包含消融与敏感性分析。
5. **超参鲁棒性好。** 一套默认超参适用于所有模型和数据集（λ=0.25, δ=0.10, τp=1.10），无需逐任务调参，实用性较强。
6. **对比公平性意识较好。** 在近似的保留率和加速水平下进行比较，并单独报告了各基线的准确率与 token 数，使得“纯压缩”和“纯长度控制”方法的缺陷都能清楚暴露。

## 8. 不足与局限

1. **基准覆盖偏向数学/科学推理。** 六个数据集全部集中在数学（GSM8K/MATH/AMC/AIME）和科学问答（GPQA），未覆盖代码生成、通用对话、复杂 agent 任务等同样依赖长推理的场景。方法在这些领域是否同样有效尚不明确。

2. **GPU 种类单一。** 只在 H20 上实验，H20 的架构特性（如注意力计算优化方式）可能影响压缩/早停方法的相对收益；缺乏对其他硬件（A100/H100/消费级 GPU）的验证。

3. **奖励估计器的局限。** ReCo 的效果高度依赖 Pilot 的奖励质量：Pilot 是蒸馏自 Skywork-o1-Open-PRM-7B 的轻量模型，在分布外问题（OOD）或新领域上奖励失真时，压缩强度、反思惩罚和早停决策都可能出错。论文未讨论 Pilot 在 OOD 场景下的鲁棒性。

4. **不同基准上的准确率表现方差较大。** 例如在 GPQA 上，ReCo 的准确率有时等于或略低于 Full CoT（如 Llama-8B 上 33.8% vs. 33.8%），从严格意义上并非“零损失”；对于需要高精度保证的场景，这种无法量化的风险可能是瓶颈。

5. **早期停止的探针成本未完全透明。** 插入探针（closing prompt + 生成答案 + 计算 PPL）本身会产生额外生成；虽然在收益上已计入总延迟（论文声称约 2%），但对于长答案或频繁触发的情况，探针成本可能被低估。

6. **反思 token 集合的构造具有一定主观性。** 需要人为挑选“Wait”“Hmm”等 token 及其变体；对于不同模型（如 Qwen3 的 tokenizer 与 DeepSeek 不同），同一集合可能覆盖不全，实际使用中需要针对模型调整。

7. **与 RL 或微调类方法缺乏直接比较。** 论文的对比对象限于推理时技术（压缩/早停/提示控制）；未与 Ada-R1、O1-pruner 等训练/微调类的高效推理方法进行对比，无法判断两者的优劣关系。
