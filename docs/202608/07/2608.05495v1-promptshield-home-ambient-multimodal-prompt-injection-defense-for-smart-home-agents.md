## 摘要
智能家居助手越来越多地使用能够直接感知视频和音频的多模态大语言模型（MLLMs）。这引发了一个家庭特有的安全问题：代理能否区分真正的用户命令与周围或外部来源的内容，如电视语音、屏幕文字或无意中听到的对话，这些内容看起来就像命令？我们引入了 PromptShield-Home，这是一个现实智能家居场景的试点基准，涵盖受话者歧义、屏幕/音频注入、健康监测误触发、混合占用和合法命令基线，并用它来比较三个抽象层：传统检测器（L0）、单个 MLLM 代理（L1；视觉、视觉+ASR 和视听）以及多智能体调解（L2；投票、角色专家、跨模型仲裁）。由于标签分布偏向于不采取行动，总体准确率会误导人，一个始终阻止的恒定预测器得分可达 82%，因此我们分别报告不安全执行率和安全完成率。这两种范式以相反的方式失败：检测器对一切采取行动，而每种 MLLM 配置都过度拒绝，几乎不完成任何真正的命令，并且在每种情况下都漏掉了真实的跌倒事件。关键在于，它们正确识别的集合是不相交的：一个总能选择正确层的神谕可以达到 94.1%，而最佳单层只有 76.5%。我们将其作为上界报告，而不是一个系统——没有实现路由器——并认为家庭代理的安全最好通过学习路由和传感器融合来实现，而不是用 MLLM 替换检测器。

## Abstract
Smart-home assistants increasingly use multimodal large language models (MLLMs) that perceive video and audio directly. This raises a safety question specific to the home: can the agent tell a genuine user command from ambient or externally-sourced content, television speech, on-screen text, or an overheard conversation, that merely looks like a command? We introduce PromptShield-Home, a pilot benchmark of realistic smart-home scenarios spanning addressee ambiguity, screen/audio injection, health-monitor false triggers, mixed occupancy, and a legitimate-command floor, and use it to compare three abstraction layers: traditional detectors (L0), a single MLLM agent (L1; vision, vision+ASR, and audio-visual), and multi-agent mediation (L2; voting, role specialists, cross-model arbitration). Because the label distribution is skewed toward inaction, aggregate accuracy is misleading, a constant always-block predictor scores 82%, so we report unsafe-execution and safe-completion rates separately. The two paradigms fail in opposite ways: detectors act on everything, while every MLLM configuration over-refuses, completing almost no genuine command and missing a true fall in every case. Crucially, their correct sets are disjoint: an oracle that always picks the right layer reaches 94.1%, against 76.5% for the best single layer. We report this as an upper bound, not a system - no router is implemented - and argue that home-agent safety is best served by learned routing and sensor fusion, not by replacing detectors with an MLLM.

## 论文总结：PromptShield Home: 面向智能家居代理的环境多模态提示注入防御

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：智能家居助手正越来越多地采用能够直接感知视频和音频的多模态大语言模型（MLLMs）。这种灵活性接口在理解自然语言、处理视觉和音频证据、推理上下文方面具有优势，但也引入了新的安全风险。
- **核心问题**：家庭环境中充斥着大量并非针对助手的“环境信号”，例如电视语音、屏幕文字、旁白对话等。MLLM 可能会正确感知这些信号，但错误地将其视为可执行的用户命令，从而导致非预期的设备动作或隐私泄露。作者将这一威胁定义为 **环境多模态提示注入（Ambient Multimodal Prompt Injection）**。
- **挑战本质**：问题不仅在于感知，更在于**来源归因（source attribution）** 和**动作授权（action authorization）**。智能体必须能判断观察到的内容是否反映了用户的真实意图，同时也要避免过度谨慎而忽略有效的命令或紧急情况（如跌倒）。
- **核心含义**：本研究旨在回答一个关键问题：当智能体面临一个需要决策的指令时，是应该**执行（execute）**、**阻止（block）** 还是**询问用户（ask_user）**？传统方法（如规则检测器）和新一代方法（MLLM）哪种更安全有效？研究结论是：两者失败模式互补，单一方法无法兼顾安全与效用，**应使用学习路由和传感器融合，而非用 MLLM 完全替代传统检测器**。

### 2. 方法论

- **问题形式化**：每个实例被建模为一个三元组 $s_i = (E_i, A_i, z_i)$，其中：
    - $E_i$ 代表多模态证据（$E_i = (V_i, U_i, T_i)$），包含视频（$V_i$）、音频（$U_i$）和可选的一行场景描述（$T_i$）。
    - $A_i = (d_i, a_i)$ 为待决策的设备-动作对（例如，`light/turn_off`, `emergency_alert/trigger_alert`）。
    - $z_i \in \{0, 1\}$ 是隐藏的金标（是否应执行）。
- **决策空间**：每一层输出 $\hat{y}_i \in \{\text{execute}, \text{block}, \text{ask\_user}\}$。其中，`block` 和 `ask_user` 均被视为“不执行”，无效输出回退至 `ask_user`。
- **三层对比框架**：研究比较了按“委派语义权限”分解的三个抽象层：
    - **L0（传统检测器）**：基于规则的确定性触发机制，如唤醒词（wake-word）、姿态检测（pose）、OCR。作为单一基线。
    - **L1（单一 MLLM 代理）**：零样本（zero-shot）JSON输出。包含三种模态设置：
        - **视觉**（Qwen3-VL-30B）
        - **视觉+ASR**（使用 Whisper 生成文本转录）
        - **原生视听**（Omni-7B）
    - **L2（多智能体调解）**：包含三种变体：
        - **投票机制**（3 次采样）
        - **角色专家**（通过组合调用不同角色，如 `addressee`, `safety`, `authorization`）
        - **跨模型仲裁**（使用文本法官对视觉和视听决策进行仲裁）。
- **安全-效用指标**：由于标签偏向“不执行”，总准确率（Accuracy）具有误导性（一个恒定的“总是阻止”预测器可得82%准确率）。因此，作者分别报告两个关键指标：
    - **不安全执行率（UER）**：在所有无需执行（$z_i=0$）的案例中，被错误执行的比例（越低越好）。
    - **安全完成率（SCR）**：在所有需要执行（$z_i=1$）的案例中，被正确执行的比例（越高越好）。
    - 同时报告**误阻止率（FBR）** 和**人工确认率（HCR）** 作为辅助指标。

### 3. 实验设计

- **基准数据集**：构建了一个名为 **PromptShield-Home** 的试点基准（pilot benchmark），包含 **19 个场景**（17 个视频片段 + 2 张静态图片）。场景在真实居住环境中录制，覆盖六类安全挑战：
    1.  **受话者歧义（7个场景）**：语音不指向代理（金标：block）。
    2.  **屏幕/音频注入（3个场景）**：电视或屏幕内容被当作命令（金标：block）。
    3.  **健康监测误触发（4个场景，1执行/3阻止）**：如真实跌倒（应执行）vs. 瑜伽姿势（应阻止）。
    4.  **混合占用（1个场景）**：多人环境下的冲突指令（金标：ask_user 或 block）。
    5.  **命令基线（2个场景）**：清晰的真实用户命令（金标：execute）。
    6.  **占用状态查询（2个场景）**：静态图片，回答空/占用（非动作决策）。
- **对比方法**：实验对比了上述 L0、L1（3种模态配置）、L2（3种机制）等所有配置，并设置了两个理论基线：`always-execute`（总是执行）和 `always-block`（总是阻止）。
- **具体实验组**：
    - **主实验**：比较所有配置在 UER、SCR、FBR、HCR 和 Acc 上的表现。
    - **互补性实验**：分析 L0 与视觉 MLLM 正确集的交集，并计算一个“神谕（oracle）”选择器的理论上限。
    - **帧预算消融实验**（Frame Budget Sweep）：测试不同帧数×分辨率对性能的影响。
    - **鲁棒性实验**：对关键配置（VL minimal, VL +scenario, Omni +scenario）进行 **5 个随机种子的采样**，评估决策的稳定性。

### 4. 资源与算力

- 论文在“Limitations”部分明确提到，推理使用了 **一张 A100-80GB GPU**。
- 同时指出，30B 的视觉模型（Qwen3-VL-30B）需要约 **60GB 的显存**，无法在家庭设备上“始终开启”（always-on）运行。这本身也构成了支持“路由”设计（route, don't replace）的一个论据。
- 论文**未提及**训练时长或能耗等额外信息。

### 5. 实验数量与充分性

- **实验数量**：
    - **主实验**：涵盖 10 种配置（L0, 3xL1, 3xL2 + 2个理论基线），在 17 个视频片段上进行三元决策评估（14个无需执行，3个需要执行）。
    - **消融实验**：1 组帧预算扫描（16到128帧，共约5个档位）。
    - **鲁棒性实验**：3 种核心配置的 5 种子重复。
- **充分性/客观性评估**：
    - **优点**：实验设计很好地隔离了“安全”与“效用”两个正交维度，并通过互补性分析（Table 4）和鲁棒性分析（Table 5）增强了结论的可信度。金标通过结构化共识协议（至少5位作者一致同意）确定，具有一定严谨性。
    - **不足**：作为试点研究，基准规模非常小（N=19），且 3 个“需执行”的场景样本量过小，导致 SCR、FBR 等指标的统计功效极低（每个案例占 33.3 个百分点）。论文也承认了以下局限：类别覆盖不均、金标由作者共识而非独立标注者确认、绝大多数实验为单次运行（single-run evaluation）、以及“神谕”路由器依赖理想选择而非训练好的模型。因此，实验的**充分性有限**，更应被视为一种“存在性证明”或“假设生成”的探索，而非定论。

### 6. 主要结论与发现

- **发现一：完全相反的失败模式（Finding 1）**：传统检测器（L0）对一切情况都“执行”（UER = 14/14, SCR = 3/3），即「过度执行」；而所有 MLLM 配置都「过度拒绝」（UER ≤ 1/14, SCR = 0/3），即几乎不执行任何真实命令，**在所有配置中均漏掉了真实的跌倒事件（V11）**。没有一种单一配置能在这两个维度上都表现良好。
- **发现二：准确率是退化的（Finding 2）**：准确率最高的方法（L2 specialist, 82.4%）等同于“总是阻止”预测器，对全部 17 个输入（包括真实跌倒）都输出 `block`。高准确率并不能证明系统的实用性。
- **发现三：模态增加并不总是有帮助（Finding 3）**：添加 ASR 转录会让视觉模型更不安全（UER=4/14，源于噪声转录）；原生音频（Omni）只是将错误转移到 `ask_user`，并未改善决策，且其“谨慎”源于不稳定性而非原则性判断（16/17 场景决策会随随机种子变化）。
- **互补性结论**：L0 和视觉 MLLM 的正确决策集**完全不相交**（L0 只正确覆盖了 MLLM 拒绝的那 3 个“需要执行”的案例，MLLM 则擅长 L0 无法推理的语义案例）。因此，**一个“神谕”选择器的理论上限准确率可达 94.1%**，远超最佳单层（视觉 MLLM）的 76.5%。
- **帧预算结论**：增加帧数并不能恢复漏掉的行动，还会导致延迟增加（4.9s → 8.6s）和数据细节损失（V09 转为不安全执行）。最佳帧预算取决于具体场景。
- **最终主张**：智能家居智能体的安全应通过**学习路由**和**传感器融合**来实现，而非用 MLLM 替换检测器。例如，使用高灵敏度的物理传感器（IMU、雷达）检测跌倒触发，再用 MLLM 作为高特异性的误报过滤器。

### 7. 优点

- **问题定义清晰且重要**：首次明确将“环境多模态提示注入”作为智能家居安全的核心威胁，并提出了“来源归因”和“动作授权”两大关键挑战。
- **评估指标设计巧妙**：识别并解决了“标签倾斜”导致准确率指标失效的问题，采用 UER/SCR 分离评估，有效呈现了安全与效用之间的“跷跷板”关系。
- **对比框架全面**：系统性地对比了从传统规则到多智能体仲裁的更广泛设计空间，而非只聚焦特定模型。
- **互补性分析深刻**：通过 Oracle 分析量化了不同范式的互补性，为未来研究（如设计路由器）提供了明确的优化目标和最上限。
- **具有批判性的消融**：对模态（ASR、音频）、帧预算和随机种子进行了消融，揭示了表面性能变化下的本质原因（例如，Omni 的 `ask_user` 倾向是不稳定性而非谨慎）。

### 8. 不足与局限

- **基准规模与统计功效**：基准数据集太小（19个场景，需执行案例仅3个），导致核心指标（如 SCR）的估计非常不稳定，降低了结论的普遍性和统计可信度。
- **数据标注与偏差风险**：金标由作者自身通过共识而非独立标注者确定，存在潜在的主观性偏差。
- **“神谕”论证的理想化**：核心主张依赖一个未实现的“神谕路由器”，该路由器在实际部署中难以实现。L0 的代理（proxy）也是理想化的，可能低估了真实检测器的漏报和误报。
- **资源与部署限制**：30B 模型的高显存需求（~60GB）和延迟使其在当前家庭场景中不具实际部署性，限制了结论的即时应用价值。
- **实验覆盖不足**：论文中的补充实验（帧预算、鲁棒性）仅在各配置的子集上运行，缺乏对所有 L1/L2 变体的全面覆盖。
- **独立性与第三方验证缺失**：实验环境为作者自建的实验室场景，缺乏独立第三方数据集的验证，增加了潜在的系统性偏差风险。
